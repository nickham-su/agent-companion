# Agent 模型与角色配置实施与验收

设计依据见 [Agent 模型与角色配置设计](<Agent 模型与角色配置设计.md>)。先用内置角色跑通 Agent 实体与多层委派，再接入角色文件。每段使用现有离线测试入口验收，最后验证飞书入口和实际模型工具调用。下文为开发目标和通过标准。

## 建立 Agent 实体和入口

### 开发工作

- 在 SQLite 增加 Agent 记录和既有会话迁移。使主 Agent 的查找、首次创建和会话绑定具备唯一性，子 Agent 创建和任务受理共用事务。 [历史存储](../../../src/agent_companion/storage/sqlite.py)
- 将飞书文字和语音入口改为定位主 Agent，由 Agent 取得内部 Session 并交给原调度器。使异步委派协议使用 `agent_id` 和 `run_id`。模型先走内置角色配置。 [应用组装](../../../src/agent_companion/app.py) · [飞书私聊路由](../../../src/agent_companion/feishu_private.py) · [会话调度器](../../../src/agent_companion/session_scheduler.py)
- 更新离线委派演示和测试输入，使用新标识继续任务。 [命令行入口](../../../src/agent_companion/__main__.py)

### 通过标准

- **主 Agent 唯一。** 同一联系人首次文字与来电同时就绪，只创建一个主 Agent 和一个 Session。重启或重拨仍用同一绑定。另一联系人查看同类输入，使用独立 Agent 和历史。
- **可创建可复用。** 连续两次用同一角色创建任务，受理结果给出不同的 `agent_id`，每个实例各用自己的历史。使用其中一个 `agent_id` 继续，得到新的 `run_id` 并接上该实例历史。新的受理结果和完成通知只提供对外标识，分别检查对应的 Agent 和运行记录。
- **归属校验。** 分别传入当前 Agent 自身、上级、同级、另一个联系人的子 Agent 和随机 ID，调用均在受理前被拒绝。错误与原工具调用对应，任务和 Agent 记录数量保持原值。
- **原子性与锁重试。** 在首次委派的绑定和受理写入之间模拟失败，检查事务回滚和队列为空。释放 SQLite 写锁后，同一受理只创建一个 Agent 和一次运行。
- **迁移。** 用已有飞书路由、主子历史、摘要和子任务记录的旧库升级两次。确认绑定 ID 一致，主子 Session 和历史可查询。旧回执里的子会话标识值可以作为迁移后该 Agent 的 `agent_id`，继续任务时仍使用原 Session。

## 接通各层 Agent 的工具与回投

### 开发工作

- 在 Runtime 中开放子 Agent 的已注册工具，保留工具调用、结果归档、模型续轮和原运行轮次计数。换用可信的运行来源做委派准入。让具有委派工具的子 Agent 可以建立自己的直属子 Agent。 [Runtime](../../../src/agent_companion/runtime/engine.py) · [工具执行](../../../src/agent_companion/runtime/tools.py) · [现有异步委派](../../../src/agent_companion/runtime/subtasks.py)
- 建立下级任务结果到委派方运行的关联。将子 Agent 的等待和续跑接入调度，同一 Agent 按序处理独立任务，下级结果可直接唤醒对应的等待运行。把受理结果、完成通知和子 Agent 的最终正文分别按设计结算。 [内部事件](../../../src/agent_companion/protocol.py)
- 移除旧分派器的并发位及固定在途受理上限，按 Agent 调度。关闭、中断和 SQLite 重试覆盖排队、运行、等待和回投各阶段。

### 通过标准

- **工具执行。** 注入一个模拟同步工具，允许其在子 Agent 被调用。检查模型收到工具结果并完成续轮，只有最终正文回投给父 Agent。模拟模型直接发出越权工具调用时，检查处理器未执行，并收到对应工具错误。
- **三级链路。** 用主 Agent、第一层子 Agent、第二层子 Agent 执行一条任务。主 Agent 先收到受理标识并能处理下一条用户输入。第一层在发出下级委派后等待，同一实例的另一项任务排队。下级结果到达后，原运行续跑，再把最终结果交回主 Agent。核对两条父子关系、两个委派调用及各自的受理和完成记录。
- **回投顺序。** 在同一子运行中委派两项下级任务，模拟一个结果早于等待、另一个延后且重复到达。两项结果分别准确关联，一次性恢复原运行，当前 Agent 的下一次独立运行不会接到旧任务的结果。另测下级返回失败后，上一级仍能从对应等待状态继续处理。
- **输入来源。** 用真实用户输入触发主 Agent 委派，再由已受理的子任务发起下一级委派，两步都成功。仅以已结束运行的纯回投触发主 Agent 时，构造模型尝试委派并检查被拒绝。工具调用中的提示词和消息角色不能改变运行来源判定。
- **串行与并行。** 一个 Agent 同时收到多次复用委派，执行全过程保持串行。向同一父 Agent 提交十个不同实例的模拟任务，检查全部受理，至少三个实例能同时进入模型执行。再让多个分支继续委派，确认总任务数不会触发委派链预算错误。
- **轮次边界。** 将 `runtime.max_tool_rounds` 设为 `2`。父子各运行独立计数，子 Agent 首轮委派后等待，结果到达时继续第二轮。让它第二轮再次调用工具，检查已发起的工具结算，运行以轮次用尽结束，并且本次运行只有两次普通模型请求。已受理下级任务照常结束，迟到结果保存到原记录。
- **故障收尾。** 注入终态与回投阶段的瞬时 SQLite 锁，确认模型和工具只执行一次。持续写失败能结束上级等待。模拟运行中关闭和异常退出，排队、执行、等待的相关记录都可核对中断状态，重启可用原 Agent ID 接新任务。

## 接入角色文件

### 开发工作

- 在应用启动时解析工作目录中 `agents/` 下的角色文件。随项目提供默认 `agents/main.md`。把头部字段解析结果、原样正文和文件名角色 ID 绑定到已确认的配置。 [现有配置加载](../../../src/agent_companion/config.py) · [现有指令入口](../../../src/agent_companion/runtime/instructions.py)
- 用角色白名单生成每个 Agent 的可执行工具集合，生成委派候选 ID 和分工说明。创建调用要求明确选角色，复用按已存角色取得配置。更新启动说明与现有部署包入口，让默认文件和创建子角色的方法可用。 [打包入口](../../../scripts/build_source_zip.py)

### 通过标准

- **识别与原文。** 在临时工作目录放置 `main.md`、`research.md` 和 `review.md`。用模拟模型检查三个角色各自收到正确的系统提示词，其中一份正文含 Markdown 标题、空行、`---` 和额外的 `+++` 行，结束分隔线后的正文逐字一致。委派可选列表为 `research`、`review`，描述与文件头一致。
- **工具白名单。** 调研角色配置 `delegate_subtask`，审阅角色配置 `tools = []`。前者收到下一级委派工具并成功创建子 Agent，后者的工具列表为空。模拟审阅角色直接发出该调用时，运行时拒绝受理。
- **参数契约。** 用角色 ID 创建和用实例 ID 复用各成功一次。分别省略 `prompt`，使用空白 `prompt`，在创建时省略角色，传未知角色，以及同时传入 `agent` 和 `agent_id`。所有错误都在受理前返回。已绑定实例按原角色配置执行。
- **启动校验。** 分别构造缺少 `main.md`、缺少结束分隔线、无效 TOML、子角色缺少描述、工具字段类型错误、未知字段和未知工具名。检查启动阶段报告足以定位错误文件或字段的诊断。只有有效主文件的目录可启动，添加子文件后重启可看到新候选。
- **变更与兼容。** 修改子角色文件并重启，已有实例在原历史上应用新的指令和白名单。删除已绑定角色的文件，复用得到角色不可用，历史仍可查询。恢复同名文件后可继续。没有 `agents/` 的旧启动目录走兼容入口，迁移后的通用子 Agent 可继续使用。

## 集成验收与交付门槛

- **离线回归。** 从仓库运行 `python -m unittest discover -s tests -v`，并运行 `python -m agent_companion --demo-subtasks`。用模拟模型、SQLite 和飞书通道替身完成上述场景，记录通过项、失败项和复现步骤。 [现有演示与测试入口](../../../README.md)
- **模型请求核对。** 用现有两个模型适配器的协议测试，核对出站委派工具定义含角色枚举与说明，模型返回函数调用后能得到对应受理或参数错误。真实模型验收使用部署选定的适配器，验证它能按分工选择角色，同一个 Agent ID 能继续历史。
- **飞书文字和语音。** 同一联系人先发文字、再发起语音，验证主 Agent 身份及历史连续性。分别在空闲、用户说话及正在生成时完成后台任务，核对回投顺序、播报打断和当前通道选路。子 Agent 的任务结果通过直属委派者回投。 [既有 Mac 验收清单](../../acceptance/mac-checklist.md)
- **交付判定。** 实体与迁移、三级委派、角色加载和白名单的离线标准通过后，可交付到本机验收。以运行记录核对关键场景中 Agent 绑定、模型请求轮次和回投顺序。真实模型和飞书通道的结果按实测记录。
