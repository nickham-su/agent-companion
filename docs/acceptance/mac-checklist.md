# 目标 Mac 实机验收清单

用专用飞书对话、合成图片和测试话术。按 [README 的安装与启动说明](../../README.md)准备 Python、lark-cli 和模型权限，不要在配置或记录中粘贴密钥。先用 `text`，再切 `voice`，最后切回 `text`；三次启动都用同一 `database`、`main_session_id`，不要并行打开第二个进程。真实模型、飞书和设备验收在目标 Mac 执行，不以离线测试替代。

## 文字模式

| 编号 | 操作 | 通过判据 |
| --- | --- | --- |
| T1 | 以 `text` 启动；从指定对话发「记住验收暗号为青石」并在同一个轮询间隔内补发两条编号文本，等过两个轮询周期。 | 启动不要求虚拟声卡；CLI 回复能复述暗号，服务同批按原顺序取到编号消息并触发一次运行，没有重复历史，不把自己的消息当输入。 |
| T2 | 发一张合成图片（例如纸上写「方框内是 37」），再发一次同条图文：「读出图片数字，用 `delegate_subtask` 计算其两倍，然后告诉我结果」。 | 单独图片与富文本都可读。分别记录三步：① 同一轮图文触发流式工具调用，以原调用 ID 回传即时受理；② 后台结果带子 Session ID 和运行 ID 回投，不当作即时工具结果；③ 主会话最终回复 `74`。图片和工具分开测不算通过。 |
| T3 | 发一条短语音条说「蓝色风筝」，并发一条普通文字。 | 主会话收到实际转写，CLI 回复能使用转写内容；同批普通文字处理正常。 |
| T4 | 在专用测试配置中临时把 `[minimax].asr_timeout` 调到足够短，以实际触发转写超时，重启后同一轮发语音条加普通文字，之后恢复正常时限。 | 单条失败语音最多一次请求，没有转写输入；原对话收到一次「语音接收失败，请重新发送。」，同批正常消息仍处理，不写入模型历史。不成功复现故障时标未验，不改为已通过。 |
| T5（选用 OpenAI Responses 时） | 用支持所填推理强度、图文和函数工具的模型完成 T2。用同一数据库、API Key、`base_url`、`model` 和 `reasoning_effort` 重启，再问合成图片中的数字。 | 工具结果续轮和重启后的请求成功；无未投递正文出现在历史中。按下列三项分别记录，不用答对数字替代密文证据。 |

- **私有项入库**：只读检查匹配的已完成助手响应是否存有非空加密推理项；只有私有记录行不算。只记录布尔结果或计数。
- **实际回传**：在本机对实际序列化并交给 HTTP 客户端的请求做仅内存核对，检查工具续轮及重启后的 `input` 是否在对应位置携带同一密文。只记录布尔结果或计数；无法核对或未观察到推理项则记待验，不用入库结果替代。
- **供应商利用**：记录请求状态、耗时与可观察回复。请求成功或模型答对不证明供应商实际利用了密文；没有独立证据时记为未证实。

更换 Key（含同一项目轮换）、地址、模型或推理强度时，既有密文不应出站，但通用历史仍可使用。若验证自定义端点，只将 Key 和模型输入发送到可信的 HTTPS 服务。旧手工标签记录不再使用。

T5 不导出请求体、密文原值、数据库或可读推理摘要，也不要开启会记录原始正文或凭据的抓包／日志。离线验收不覆盖真实 OpenAI、自定义端点或目标 Mac。

## 实时语音模式

| 编号 | 操作 | 通过判据 |
| --- | --- | --- |
| V1 | 按 README 安装 `voice` 依赖、准备 Silero 模型和两台 CoreAudio 虚拟设备。在飞书选择各自扬声器和麦克风，切 `voice` 重启，手动接通。分别先说一句，再保持安静听完整回答。 | 程序可打开两路设备；对端讲话能转写，对端能听到合成回复；安静时播报不会触发自己的 VAD 或进入 ASR。录入与播放路径无明显串音。 |
| V2 | 说 3 轮简短测试句，每轮停说并等到首段出声。记下停说至对端听到首段回复的秒数。 | 每次完整话轮只提交一次文件转写；收到首段即可播、不等整段回答完成。记录三次延迟及是否满足使用方事先约定的可接受值，无约定则记录实测值、待确认。 |
| V3 | 要求回复持续几秒；听到开头后说「停，改答蓝色」，停说等转写。再试一次在旧回复还没出声时讲话。 | 旧播报停止且不会在 ASR 等待或完成后恢复；已交设备的少量尾音可自然结束。第一次历史只留大致确认前缀；第二次若旧回复未交付任何音频，记零投递。新语音进入同一主 Session；没有凭语音打断取消模型或工具。 |
| V4 | `voice` 下从飞书对话发一条测试语音条和一条文字，再按 T4 模拟语音条超时，之后恢复配置。 | 成功转写作为同一主会话输入，模型回复走语音；失败通知仍只走原飞书对话的文字，不播报固定通知。 |
| V5 | 手动挂断，恢复 `text`、重启，发「前面记住的验收暗号是什么？」。 | CLI 返回「青石」，不打开音频设备；同一主 Session 中可查到通话转写与已确认的语音回复，未补发失败或未知投递。 |

## 子任务回投：忙和闲各验一次

| 编号 | 操作 | 通过判据 |
| --- | --- | --- |
| S1 | 委派一项需一些时间的合成撰写任务，要求主会话先简短告知已受理；在任务完成前再次发文字要求较长回答，让主会话在结果回来时仍有回复在生成或投递。 | 主会话先处理新输入；子任务完成与入队发生在该回复收尾前，结果只在下一处安全边界纳入，不插入本轮工具调用块或打断投递。若时序没重合，重做而不是判通过。 |
| S2 | 再委派一项任务；看到受理后不发任何新消息，并让主会话先空闲。 | 完成后无需新输入，回投独立唤醒主会话并收到结果。两场景分别核对 `child_session_id`、`run_id`、完成及入队时间；主历史只收任务结果，原任务与执行记录在子 Session。子会话没有单独发外部回复。 |

历史和回执可在本机用只读方式核对 `messages`、`reply_outcomes`、`subtask_runs`；`enqueued_at` 仅表示入队，不证明主会话已消费。不要上传历史库或原始日志。记录格式：`编号 | 模式与版本（macOS/Python/CLI） | 通过/失败/待验 | 简短重现步骤 | 预期与实际 | 耗时或脱敏证据`。对外记录仅留合成话术、状态、时长和经脱敏的关联 ID；删去密钥、会话登录材料、用户标识、私人消息、设备录音和绝对个人路径。
