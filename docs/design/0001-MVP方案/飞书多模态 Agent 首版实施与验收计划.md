`agent-companion` 不一次性铺开所有模块。先用模拟通道把 Runtime、历史和投递确认跑通，再接入子任务、飞书消息和实时语音。每一阶段都要有能独立运行的验收场景，最后交付代码包和 Mac 验收清单。设计依据：[飞书多模态 Agent 首版架构方案](https://chatgpt.com/space/page_8e2e95be15388191928b2f165fe15e5f)。

# 实施顺序与验收分工

\*\*依赖顺序：\*\*阶段一是共同底座。阶段二（子任务）、阶段三（飞书消息）和阶段四（实时语音）都依赖底座；建议按顺序验收，阶段三与四共享 MiniMax 文件转写适配器。最后在阶段五做集成和交付。各阶段失败只阻止依赖该能力的验收，不阻止其他独立工作。

\*\*云端与本地的边界：\*\*云端按官方文档实现 DeepSeek、MiniMax 和飞书 CLI 的适配，用模拟响应、本地 SQLite、模拟 CLI、音频样本和虚拟设备替身验证流程。云端没有模型 API Key，不打真实模型接口，也不要求接入真实飞书或目标 Mac。苏叶部署后在本地配置密钥、登录飞书并执行真实验收。已验证的飞书 CLI 用户权限不作为开工门槛。

# 阶段一：主 Session 与交付回执

\*\*工作与产物。\*\*搭建单进程 Python 工程、启动配置、模型与通道接口、静态工具注册，以及可重复运行的模拟验收。SQLite 按 Session 存储历史，使用全局自增消息 ID；实现按会话读取、上下文预算检查、保留尾部原文的压缩，以及模型请求投影。实现 DeepSeek 适配器，按官方协议构造文字、图片和工具消息并解析流式响应。配置和接口设计不依赖模型密钥或音频设备。

\*\*云端验收。\*\*用模拟通道分别送入纯文本响应、纯工具响应和混合响应。混合响应中先回工具结果、后回文本回执，再交换两者到达顺序；两次都只有在模型流结束、工具结果已落库且文本回执已处理后，才允许在安全边界纳入队列输入。纯工具不等回执，纯文本不等工具。

\*\*云端验收。\*\*分别回传全量、部分、零投递、明确失败和超时未知。通过标准：历史正文只包含确认部分；失败和超时都能继续处理下一条，超时不自动重发；内部状态不进模型请求或压缩摘要。纯文本空条目不投影；混合响应仍保留工具调用和对应结果。重启后历史仍可读取。

\*\*云端验收。\*\*用模拟模型产生一段足够长的历史并触发压缩。通过标准：模型请求看到最新摘要和同一 Session 的原文尾部，工具调用和结果不被拆开，压缩前的原文仍可查询。模拟 DeepSeek 流式响应验证图片和工具调用的请求序列；实际模型组合放到本地验收。

**云端验收。**用模拟 DeepSeek 请求检查思考模式默认显式关闭，开启后带工具的后续请求能按协议回传原始 `reasoning_content`，该字段不进入对外正文、日志或压缩摘要；用缺少该字段的旧历史验证从关闭切到开启时的请求投影。用模拟时钟检查模型单次请求的默认 60 秒总时限及配置覆盖，再模拟超时和断流。通过标准：请求进入失败终态，不执行未收齐的工具调用，保留已确认的正文，主 Session 能处理下一条输入。

# 阶段二：异步子任务与回投

\*\*依赖与产物。\*\*依赖阶段一的 Runtime、历史、队列和工具边界。实现异步委派工具、子 Session 独立运行和持久化、结果回投主队列。委派立即返回可复用的子 Session ID 和本次运行 ID；子 Session 再次运行时沿用会话 ID，另给运行 ID。

\*\*云端验收。\*\*用一个可控制暂停和结束的子任务制造两种场景。第一种：子任务执行时给主 Session 发新输入，主 Session 必须仍可处理；在主 Session 正忙时完成子任务，结果只能在下一处安全边界纳入。第二种：主 Session 先进入空闲，再让子任务完成；无需发新用户消息，结果即触发一轮。

**云端验收。**模拟委派提交失败。通过标准：不等待子任务回投，也不靠单独的工具超时收尾；失败结果按原工具调用 ID 落库并回传给模型，主 Session 仍能继续处理输入。

\*\*通过标准。\*\*两种场景都能通过会话 ID 和运行 ID 查到结果来源；主、子历史各自落库，主历史只纳入任务结果而不复制子过程；子任务不得绕过主 Session 直接向飞书或语音输出。任务开始、完成和回投可从测试记录核对。

# 阶段三：飞书文字、图文与语音条

\*\*依赖与产物。\*\*依赖阶段一的批量提交和投递接口。以飞书 CLI 用户身份每 10 秒轮询指定对话，按飞书消息 ID 去重，按原顺序解析文字、独立图片、含图文的富文本及语音条。图片下载和语音条转写放在通道侧。实现 MiniMax 完整文件转写适配器：语音条下载后走该接口，实时语音阶段复用。`text` 模式用 CLI 发回复，不打开音频设备。

\*\*云端验收。\*\*用模拟 CLI 提供含重复消息的两次轮询，并让同一批语音条的模拟转写延后返回。通过标准：同批完成规范化后按原顺序整批入队，空闲时只启动一次运行，忙时整批到安全边界才纳入；图文富文本保持在同一条输入；不会重复投递，不会把自己的回复当成新输入；文字发送成功、失败、超时都能转成正确的 Runtime 回执。

**云端验收。**在 `text` 和 `voice` 模式下，分别模拟飞书语音条转写失败和超时，并混入正常消息。通过标准：每条失败语音只发起一次转写请求、不入队；通道在原飞书对话发一次文字通知「语音接收失败，请重新发送。」，不走语音播报；同批正常消息按原顺序入队。

\*\*苏叶本地验收。\*\*启动 `text` 模式，用真实飞书依次发文字、独立图片、同条图文和语音条，再在一次轮询间隔内连续发多条。检查收到 CLI 文字回复，回答用到了图文和转写内容，同批只触发一次运行，历史不重复。用一条图文及确定会调用工具的测试指令，在同一轮验证图片输入、流式工具调用、回传工具结果和最终回复。

# 阶段四：本机实时语音

\*\*依赖与产物。\*\*依赖阶段一的回复流和回执接口，复用阶段三的文件转写适配器。实现与 IM 无关的 Mac 音频 I/O、Silero VAD 打断和话轮结束策略、MiniMax TTS 适配器、TTS 分段调度和播放队列。`voice` 模式启用双向虚拟音频。用户停说达到默认 1 秒静默后，提交该话轮的完整录音；TTS 每段一次提文、流式收音频；本地 VAD 判定打断不等待 ASR。飞书接听、挂断由用户手动操作，不做窗口识别或运行时自动切换。

\*\*云端验收。\*\*用音频样本及模拟设备时钟驱动输入和输出，模拟 VAD 边界、MiniMax 转写和分块音频响应。通过标准：一轮话音对应一次文件提交，上传内容是受支持格式而非裸 PCM；音频块在整段收齐前即可开始播放，下一段只在上一段音频流收完且待播低于配置阈值时提交。打断后清掉未发内容、停止在途 TTS、忽略迟到音频；Runtime 的模型生成和工具不被语音状态取消。

\*\*云端验收。\*\*分别构造正在播报、仅在调工具、用户仍在说时旧回复才开始输出三种情形。通过标准：分别记录确认前缀、让工具继续并在转写完成时入队、以及抑制旧回复并回零投递。已交设备的小量音频不强制撤回；历史以本机交给设备的进度为准，不假定知道飞书对端听到了哪一个字。

**云端验收。**让旧回复在用户停说后、ASR 尚未返回时才开始输出文本。通过标准：不播报，立即回零投递。另测旧回复已播一部分再打断，只确认已发前缀。两种情形都分别模拟 ASR 之后成功和失败，旧回复都不恢复播报，模型生成和工具执行不被取消。

\*\*苏叶本地验收。\*\*改为 `voice` 模式并重启，把飞书扬声器接到输入虚拟线路、飞书麦克风接到输出虚拟线路，手动接通电话。说一轮并停顿，确认真实 MiniMax 转写和双向播报可用；让回复持续几秒，中途开口打断，再说一句，检查旧回复不再继续送入待播队列、历史只留大致已发前缀、新转写能进入同一个主 Session。手动挂断后改回 `text` 并重启，确认主历史保留、回复恢复走 CLI。

# 阶段五：集成、打包与交付

\*\*依赖与产物。\*\*阶段一至四的云端验收通过后，交付可下载代码包、依赖与启动说明、无密钥的配置样例、模拟测试入口、两种模式的 Mac 验收清单，以及一份区分「云端已验证」「本地待验收」的结果记录。代码包不包含密钥、登录材料、测试数据库或真实媒体；本阶段不创建 GitHub 仓库，也不推送代码。

\*\*云端交付门槛。\*\*从干净的目录按说明安装，在无模型密钥、无飞书账号、无虚拟声卡的情况下完成模拟验收。用同一份测试数据库串起文字输入、异步回投、语音交付与打断、投递失败和重启恢复；结果记录必须写清楚哪些路径只验证过模拟接口。

\*\*首版最终验收门槛。\*\*苏叶在 Mac 完成阶段三与四的真实验收，并任选一个实际任务验证主、子会话分开存储以及结果在主会话忙和闲时的两种回投。每项记录通过或失败；失败时注明运行模式、步骤、预期与实际结果，必要时提供去除密钥和私密内容的日志。模型真实调用、目标 Mac 音频和真实飞书路径没有通过之前，不将首版标记为已验收。
