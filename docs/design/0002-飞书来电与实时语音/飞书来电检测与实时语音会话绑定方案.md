# 飞书来电检测与实时语音会话绑定方案

Agent Companion 在 Mac 上根据来电人动态接入实时语音。同一个人的飞书私聊和实时通话共用一个主 Session，语音通道只绑定到当前这通电话。`[feishu].mode = "voice"` 在多私聊文字链路上启用自动接听；默认 `text` 不监听来电或查询会议。 [启用与验收步骤](../../../README.md#本机启用飞书自动接听)

## 本机窗口检测

在 macOS 本地轮询窗口。空闲时由窗口变化发现来电，发现候选浮窗后才调用飞书 CLI 查身份。以下特征来自 2026 年 11 月 23 日在本机的一对一飞书语音通话实验，环境为 macOS 27.0.1 和飞书 CLI 1.0.100。

| 特征 | 未接听的来电浮窗 | 接通后的通话主窗口 |
| --- | --- | --- |
| 所属应用 | 飞书会议，Bundle ID 为 `com.electron.lark.iron` | 同一应用 |
| 窗口标题 | 「飞书会议」，另有一条同位置的空标题窗口记录 | 「飞书会议」，另有一条同位置的空标题窗口记录 |
| Core Graphics 窗口层级 | `25` | `0` |
| 辅助功能子角色 | `AXSystemDialog` | `AXStandardWindow` |
| 本次尺寸 | `368 × 86` 点，位于屏幕右上角 | `928 × 715` 点 |

- 首版沿用探针的所属应用名、窗口层级和几何特征，未引入辅助功能遍历。通过主窗口标题完成初次确认后，按进程和窗口号码跟踪，不再要求标题、层级或尺寸恒定。
- 同一位置的两条浮窗记录对应一个来电提示。按所属进程和窗口边界合并，点击前再检查浮窗仍在及目标点的窗口归属。
- Python 实测可以读取浮窗外层的 `AXWindow` 和 `AXGroup`。来电人文字及两个按钮区域的命中结果都是该容器，接听实验使用窗口坐标定位按钮。 [Apple 窗口元数据接口](https://developer.apple.com/documentation/coregraphics/kcgwindowlayer) [Apple 辅助功能子角色](https://developer.apple.com/documentation/appkit/nsaccessibilityprotocol)
- 窗口层级和子角色是当前版本的实测特征。升级飞书或扩展到其他通话入口时，重新验证响铃和接通窗口。

## 接听前确认来电人

检测到浮窗后，以与文字链路相同的飞书 CLI 用户和应用上下文查询活跃会议，再用该会议的 `meeting_id` 查询详情。当前用户授权需包含 `vc:meeting.meetingevent:read`。

```bash
lark-cli vc +meeting-list-active --as user --format json
lark-cli vc meeting get --as user --meeting-id '<meeting_id>' --with-participants --user-id-type open_id --format json
```

一对一来电在还未接听时就返回活跃会议。实测此时 `meeting.status = 1`，来电人的 Open ID 同时出现在 `meeting.host_user.id` 和 `meeting.participants[].id`，参会人列表当时只有来电人。接通后实测 `meeting.status = 2`。会议身份无法与本次来电唯一对应时，暂不自动接听。其他会议邀请场景需单独验证发起人字段。

## 模拟点击接听

浮窗和点击点使用同一个 macOS 屏幕坐标系。偏移沿浮窗边缘计算，单位为点。人工指向接听按钮中心时，实测距右边缘向左 `35.76` 点、距上边缘向下 `44.56` 点。自动接听采用已验证的整数偏移，距右边缘向左 **35 点**，距上边缘向下 **45 点**。

```text
点击 X = 浮窗左边缘 X + 浮窗宽度 - 35
点击 Y = 浮窗上边缘 Y + 45
```

每次用当前浮窗的位置计算点击点。确认浮窗仍匹配、落点仍命中目标后，模拟一次鼠标左键按下和释放。Mac 需允许启动脚本的应用发送鼠标事件。独立探针已用这组偏移接通一通测试电话，正式流程在识别来电人并建立绑定后执行点击。 [Python 单次接听探针](feishu_answer_once.py)

## 实时语音会话的绑定与解除

### 响铃时绑定并准备设备

- 空闲或未绑定时，虚拟输入线路的音频直接丢弃，无缓冲。
- 查到来电人的 Open ID 后，通过现有多私聊路由取得或创建他的主 Session。首次来电和首次文字输入复用同一个会话入口，同一用户只有一个 Runtime 队列。记录这次的 `meeting_id`、来电人和主 Session，供本次通话校验。 [现有多私聊路由](../../../src/agent_companion/feishu_private.py)
- 绑定后先打开本通的语音设备，再用原判定时限内的剩余时间复查飞书 CLI。两次 `meeting_id` 和来电人 Open ID 都一致，且原路由、双路设备、浮窗和点击落点仍有效才点击接听。确认接通前不保留输入帧、不转写、不播报。确认后才开启收音，VAD、ASR、打断和 TTS 沿用现有逻辑。 [现有语音通道](../../../src/agent_companion/speech/voice.py)

### 接听后确认通话

- 点击后在短时限内等待同一进程出现唯一主窗口，并确认响铃浮窗已经消失；确认时必须仍能检查到两端设备都在运行，不再等待一次 CLI 查询。首版不与其他已开的通话同时运行。
- 点击失败、设备失活、确认来电已结束，或到时限仍未接通时，立即解除本次绑定并清理两端音频。接通确认时限在实机联调时确定。

### 通话结束时清空音频

- 接通后持续检查这通电话的主窗口。第一次在全量窗口列表里找不到本通的窗口身份，或者枚举报错，即同步关闸。不把仅遮挡、最小化或切换桌面且仍在全量列表中的窗口当作挂断。
- 确认本通结束时，先立即解除绑定并关闭本通的音频输入和输出，再让在途任务异步收尾。丢弃预录、未提交的录音和转写，以及排队或尚未播放的合成音频。取消在途 ASR、TTS 并丢弃迟到的结果。
- 语音输入和回复跟随原通话绑定。只有该绑定还有效时，转写才可提交给主 Session，回复才可进入虚拟输出线路。下一通电话创建自己的语音通道和绑定。
- 挂断后缩短该通当前模型流的截止，不再开始旧通话的模型续轮。工具和已交设备的语音回执仍按原机制结算；首版要求模型适配器响应取消，不强杀不合作的适配器。主 Session、已归档的历史和文字通道继续保留。文字回复不改变出口。语音轮触发的子任务只能回投原通话，若已挂断则仅保留子任务终态。可给原私聊发送确认正文副本。

## 联调验证

- 让同一联系人先发文字再打电话，核对两条链路进入同一主 Session。再用另一位联系人拨打，确认语音和历史会随来电人切换。
- 在首次来电、接通失败和正常挂断时，核对绑定时点、开始收音时点及音频队列的清理。
- 在通话窗口被遮挡、最小化和关闭时，核对窗口检测结果。在旧通话的 ASR 或 TTS 尚未结束时切换来电，核对旧音频和迟到结果的去向。
