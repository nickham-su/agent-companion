# Agent 模型与角色配置实施与验收

设计依据见 [Agent 模型与角色配置设计](<Agent 模型与角色配置设计.md>)。先用离线角色夹具跑通 Agent 实体与多层委派，再接入正式角色文件。每段使用现有离线测试入口验收，最后验证飞书入口和实际模型工具调用。下文为开发目标和通过标准。

## 建立 Agent 实体和入口

### 开发工作

- 在 SQLite 持久化 Agent 与 Session 的绑定，保证主 Agent 的查找和首次创建具备唯一性。将委派受理记录和运行记录分开，子 Agent 创建、Session 绑定和委派受理共用事务。本期不实现旧库或历史标识兼容。 [历史存储](../../../src/agent_companion/storage/sqlite.py)
- 将飞书文字和语音入口改为定位主 Agent，由 Agent 取得内部 Session 并交给原调度器。委派入队后立即返回 `status: accepted`、`agent_id` 和 `delegation_id`，Runtime 实际启动运行时才生成 `run_id`。 [应用组装](../../../src/agent_companion/app.py) · [飞书私聊路由](../../../src/agent_companion/feishu_private.py) · [会话调度器](../../../src/agent_companion/session_scheduler.py)
- 更新离线委派演示和测试输入，用角色 ID 创建、用 Agent ID 继续任务。内置角色仅用于离线测试和开发演示，不作为正式启动的回退。 [命令行入口](../../../src/agent_companion/__main__.py)

### 通过标准

- **主 Agent 唯一。** 同一联系人首次文字与来电同时就绪，只创建一个主 Agent 和一个 Session。重启或重拨仍用同一绑定。另一联系人的输入使用独立 Agent 和历史。
- **可创建可复用。** 连续两次用同一角色创建子 Agent，受理结果给出不同的 `agent_id`，各自维护历史。使用其中一个 `agent_id` 继续，回执沿用该实例 ID，返回新的 `delegation_id`，不返回 `run_id`；检查受理不预建运行，实际执行接上该实例历史。用新版本库重启后再次复用，确认身份和历史连续。
- **归属校验。** 分别传入当前 Agent 自身、上级、同级、另一个联系人的子 Agent 和随机 ID，调用均在受理前被拒绝。错误与原工具调用对应，委派和 Agent 记录数量保持原值。
- **原子性与锁重试。** 在首次委派的绑定和受理写入之间模拟失败，检查事务回滚和队列为空。释放 SQLite 写锁后，同一受理只创建一个 Agent、一条委派记录，只入队一次。

## 接通各层 Agent 的工具与回投

### 开发工作

- 主、子 Agent 共用 Runtime 的输入、工具执行及续轮。主入口保留说话和转写门控，子入口直接放行到 Runtime 队列，不抢占当次模型请求。按角色白名单、可信输入来源和直属归属校验委派；主、子 Agent 都可在仅收到下级回投时继续委派，不扩大定时器等其他内部输入的授权。 [Runtime](../../../src/agent_companion/runtime/engine.py) · [工具执行](../../../src/agent_companion/runtime/tools.py) · [现有异步委派](../../../src/agent_companion/runtime/subtasks.py)
- 新任务和异步结果进同一条队列；空闲时开新一轮，运行中在安全边界纳入；子 Agent 每轮的最终回复都交给直属父级。不设置等待下级或恢复旧运行的路径。统一的内部信封标明来源 `agent_id`、来源 `run_id`，并带齐当轮直接纳入的父级委派对应的 `delegation_id`。只收到下级回投的新一轮沿用同一个信封和回投机制，不要求追溯此前的父级委派。信封不指定父级用哪次运行处理。 [内部事件](../../../src/agent_companion/protocol.py)
- 移除旧分派器的并发位及固定在途受理上限，不新增任务数、委派深度或并发限制，保留单次运行的模型请求轮次上限。关闭、中断和 SQLite 有限重试覆盖排队、执行和回投。

### 通过标准

- **工具执行。** 注入一个模拟同步工具，允许其在子 Agent 被调用。检查模型收到工具结果并完成续轮，只有最终正文回投给父 Agent。模拟模型直接发出越权工具调用时，检查处理器未执行，并收到对应工具错误。
- **三级链路。** 主 Agent 委派 A，收到受理回执后可继续处理用户输入。A 委派 B 并在 B 完成前结束当轮，回复进入主 Agent 调度器。B 的晚到结果进入空闲 A 的调度器，以新的 `run_id` 开一轮；A 只收到 B 的结果就能继续委派 C。C 的结果返回 A 后，A 的最终回复进入主 Agent 调度器。核对各次回投只到直属父级；A 的不同运行各自交付回复，不恢复旧运行；纯下级回投触发的新一轮也使用同一个信封和回投机制。
- **安全边界与关联。** 在 A 正在生成时，让下级结果和父级新委派按顺序入队。检查不抢占模型请求，工具结算后若有续轮，输入按队列顺序纳入当前运行，保留 `run_id`；若没有续轮，留给后续运行处理。两条父级委派直接纳入同一轮时，只回投一条最终回复，且信封带齐两个 `delegation_id`。按来源 Agent 和来源运行识别重复事件，同一事件不重复消费。下级运行失败时，错误也经同一输入路径到达父级。
- **输入来源。** 真实用户输入发起主 Agent 委派、已受理的父级委派发起下一级委派均成功。对主、子 Agent 分别验证纯下级回投能触发委派；定时器等其他内部输入不因此获得新权限，模型消息或工具参数也不能伪造输入来源。
- **串行与并行。** 一个 Agent 同时收到多次复用委派，模型执行保持串行，输入可并入同一运行。向同一父 Agent 提交十个不同实例的模拟任务，检查全部受理，至少三个实例能同时进入模型执行。再让多个分支继续委派，确认不会触发旧固定准入或新增委派预算限制。
- **轮次边界。** 将 `runtime.max_tool_rounds` 设为 `2`。子 Agent 首次模型请求发起委派，结算后不等结果，继续下一次模型请求；安全边界纳入输入不重置计数。让第二次请求再次调用工具，检查已启动的工具先结算，本次运行只发出两次普通模型请求并以轮次用尽结束。已受理的下级照常完成，晚到回投触发的新运行独立计数，父级的运行也独立计数。
- **故障收尾。** 在终态写入与回投记录阶段注入瞬时 SQLite 锁，只重试失败的数据库操作，检查模型、工具和回投不重复执行。终态持续无法写入时有可核对的诊断。模拟关闭与异常退出，核对排队委派和未结束运行标记中断；重启后不自动重跑或补投，原 Agent ID 仍可接新任务。

## 接入角色文件

### 开发工作

- 正式启动时解析工作目录中 `agents/` 下的顶层角色文件，跳过 `*.example.md`，要求存在有效的 `main.md`。把头部字段解析结果、原样正文和文件名角色 ID 绑定到已校验的配置，不读取旧 `AGENTS.md`。 [现有配置加载](../../../src/agent_companion/config.py) · [现有指令入口](../../../src/agent_companion/runtime/instructions.py)
- 用角色白名单生成每个 Agent 的可执行工具集合，生成委派候选 ID 和分工说明。创建调用要求明确选角色，复用按已存角色取得配置。更新启动说明与部署包入口：仓库及部署包只提供 `agents/main.example.md` 和 `agents/sub.example.md`，`.gitignore` 忽略 `/agents/*` 并仅放行这两个模板。 [打包入口](../../../scripts/build_source_zip.py)

### 通过标准

- **识别与原文。** 在临时工作目录放置两个模板和 `main.md`、`research.md`、`review.md`。用模拟模型检查三个实际角色各自收到正确的系统提示词，其中一份正文含 Markdown 标题、空行、`---` 和额外的 `+++` 行，结束分隔线后的正文逐字一致。委派可选列表只有 `research`、`review`，描述与文件头一致。
- **工具白名单。** 调研角色配置 `delegate_subtask`，审阅角色配置 `tools = []`。前者收到下一级委派工具并成功创建子 Agent，后者的工具列表为空。模拟审阅角色直接发出该调用时，运行时拒绝受理。
- **参数契约。** 用角色 ID 创建和用实例 ID 复用各成功一次。分别省略 `prompt`，使用空白 `prompt`，在创建时省略角色，传未知角色，以及同时传入 `agent` 和 `agent_id`。所有错误都在受理前返回。已绑定实例按其绑定角色执行。
- **启动校验。** 分别在缺少 `agents/`、有目录但只有模板时启动，检查均停止并提示从 `main.example.md` 创建 `main.md`。对缺少结束分隔线、无效 TOML、子角色缺少描述、工具字段类型错误、未知字段和未知工具名，检查启动失败且诊断能定位文件和错误位置或字段。只有有效主文件时可启动，即使主角色白名单包含委派也不显示该工具；添加实际子角色后重启可看到新候选。
- **角色变更。** 修改子角色文件并重启，已有实例在原历史上应用新的指令和白名单。删除已绑定角色的文件，复用得到角色不可用，历史仍可查询。恢复同名文件后可继续。
- **模板交付。** 检查版本控制忽略本地角色文件，部署包的 `agents/` 只包含两个模板，不包含本地配置。

## 集成验收与交付门槛

- **离线回归。** 从仓库运行 `python -m unittest discover -s tests -v`，并运行 `python -m agent_companion --demo-subtasks`。用模拟模型、SQLite 和飞书通道替身完成上述场景，记录通过项、失败项和复现步骤。 [现有演示与测试入口](../../../README.md)
- **模型请求核对。** 用现有两个模型适配器的协议测试，核对出站委派工具定义含角色枚举与说明，模型返回函数调用后能得到对应受理或参数错误。真实模型验收使用部署选定的适配器，验证它能按分工选择角色，同一个 Agent ID 能继续历史。
- **飞书文字和语音。** 同一联系人先发文字、再发起语音，验证主 Agent 身份及历史连续性。分别在空闲、用户说话及正在生成时完成后台任务，核对回投顺序、播报打断和当前通道选路。子 Agent 的结果通过直属父级的调度器回投。 [既有 Mac 验收清单](../../acceptance/mac-checklist.md)
- **交付判定。** Agent 实体与重启复用、三级委派、角色加载和白名单的离线标准通过后，可交付到本机验收。以委派及运行记录核对 Agent 绑定、模型请求轮次和回投顺序。真实模型和飞书通道的结果按实测记录。
