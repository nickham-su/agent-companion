# Agent Companion：会话调度器重构方案

版本：设计稿 1.1｜目标分支：v0.1｜2026-11-24

## 1. 背景与范围

本方案重建此前讨论的设计文档，并纳入三项补充要求：控制抽象范围、结构化调度日志、并发测试前置。依据此前对 v0.1 的调研记录及项目原架构文档；本次未重新核验全部源码，具体函数签名与语音接线须在实施前核对。

现有设计采用 Python 单进程、异步主会话与独立子会话、SQLite 历史、工具调用循环及通道投递确认。此前调研指出子任务结果可唤醒主会话，工具续轮也可能吸收队列输入。因此仅修改子任务回投入口不足以解决抢话问题。

目标：用户输入期间不由后台结果触发主会话；空闲时主动汇报；有效输入与待处理结果合并；无有效转写时恢复调度；子任务不受语音状态影响。

不重写模型适配器、工具系统、历史压缩或音频流水线。不引入新的模型、消息中间件、插件框架或分布式调度。

## 2. 架构与职责

采用组合模式：每个 Session 拥有独立 Scheduler 实例，共享调度引擎实现，注入不同 Policy。Runtime 负责模型与工具执行，不自行消费外部事件。语音组件负责检测、合成和播放；子任务管理器负责委派与结果回投。

``` mermaid
flowchart TD
 V[语音与文字输入] --> M[主会话 Scheduler]
 S[子任务结果] --> M
 M --> P[InteractivePolicy]
 Q[委派任务] --> C[子会话 Scheduler]
 C --> T[TaskPolicy]
 P --> R[共享 Runtime 执行实现]
 T --> R
 R --> H[独立 Session 历史]
 C --> S
```

图中 Runtime 表示共享代码而非共享运行锁。不同 Session 可以并行，同一 Session 最多一个活动执行。

  能力                      通用引擎           主会话策略       子会话策略
  ------------------------- ------------------ ---------------- ------------
  事件接收、排队、运行 ID   是                 复用             复用
  单会话串行、取消协调      是                 复用             复用
  用户输入与输出状态        否                 是               否
  后台结果合并、交互优先    否                 是               否
  任务容量与执行准入        通用执行额度接口   不占子任务额度   是
  结果回投                  事件接口           接收             发送

## 3. 状态与事件

主会话维护三个正交状态机；待处理事件池是数据而非第四个状态机。

  -------------------------------------------------------------------------------------------------------------
  状态机                  状态                                             转移依据
  ----------------------- ------------------------------------------------ ------------------------------------
  用户输入                IDLE / SPEAKING / ENDPOINTING / TRANSCRIBING     VAD、静默计时、ASR 终态

  执行                    IDLE / RUNNING / WAITING_BOUNDARY / CANCELLING   启动、响应安全边界、取消确认、结束

  输出                    IDLE / ACTIVE / STOPPING                         输出开始、终态回执、打断确认
  -------------------------------------------------------------------------------------------------------------

``` mermaid
stateDiagram-v2
 [*] --> IDLE
 IDLE --> SPEAKING: 开口
 SPEAKING --> ENDPOINTING: 静默
 ENDPOINTING --> SPEAKING: 再开口
 ENDPOINTING --> TRANSCRIBING: 话轮结束
 TRANSCRIBING --> IDLE: 有效或无效或超时
 TRANSCRIBING --> SPEAKING: 新话轮
```

新话轮与旧 ASR 重叠时以 turn_id 跟踪所有未终结输入；只有全部实时输入结束才算 IDLE。旧转写按话轮顺序处理或明确作废，不得覆盖新状态。输出 ACTIVE 包含合成、待播、播放及尚未确认的投递；文字模式不启用语音状态，但仍等待文字回执。

子会话只维护执行状态及任务生命周期：QUEUED、RUNNING、SUCCEEDED、FAILED、CANCELLED（取消中可单独记录）。同一子会话按序执行，不同子会话并行。

事件建议字段：event_id、session_id、kind、source、sequence、created_at、turn_id/run_id/reply_id（适用时）、payload。sequence 由调度入口分配；时间戳仅用于诊断。

  ----------------------------------------------------------------------------------
  事件                                          处理
  --------------------------------------------- ------------------------------------
  SPEECH_STARTED / SPEECH_PAUSED / TURN_ENDED   更新输入状态；确认打断时请求停播

  ASR_FINAL / ASR_EMPTY / ASR_FAILED            原子更新话轮状态并入队有效输入

  USER_BATCH                                    保留飞书同批消息及图文边界

  SUBTASK_RESULT                                去重后暂存，不直接运行 Runtime

  RESPONSE_BOUNDARY / RUN_FINISHED              更新执行状态并重新决策

  DELIVERY_FINAL                                记录全量、部分、零投递、失败或未知

  CANCEL_REQUEST / CANCELLED                    请求取消及确认

  CAPACITY_AVAILABLE                            唤醒等待额度的子会话
  ----------------------------------------------------------------------------------

## 4. 主会话调度

``` mermaid
flowchart TD
 A[接收事件并更新状态] --> B{实时输入尚未结束?}
 B -->|是| W[暂存外部输入和后台结果]
 B -->|否| C{已有执行或输出未终结?}
 C -->|是| D{到达安全边界?}
 D -->|否| W
 D -->|是| E[按策略处理续轮]
 C -->|否| F{有待处理输入?}
 F -->|否| W
 F -->|是| G[优先选用户输入并合并后台结果]
 E --> G
 G --> H[启动或继续模型调用]
 H --> A
 W -.下一事件.-> A
```

图中安全边界分支只适用于允许续轮的当前运行；最终响应结束后释放运行槽，再按空闲规则启动新运行。若工具续轮没有外部输入，也必须正常推进。

  条件                           行为
  ------------------------------ ------------------------------------
  空闲且结果到达                 主动启动一次运行
  正在说话、静默判断或等待 ASR   暂存后台结果
  ASR 有效且旧运行已安全结束     用户输入优先，合并待处理结果
  ASR 空、失败或超时             解除输入门控，重新检查待处理结果
  运行中收到结果                 等安全边界，且实时输入已结束才消费
  TTS 未播完                     不启动新的后台回复
  用户打断                       停播，保留确认前缀；不自动取消工具
  普通文字或图片到达             入队，不抢占当前播报
  多个结果到达                   按序批量纳入，避免每个结果独立唤醒

### 4.1 工具续轮与安全边界

沿用原架构：模型流结束、该批工具结果全部落库、对外文本终态回执已处理，才到达安全边界。纯工具不等输出，纯文本不等工具。

建议第一版在安全边界若实时输入尚未结束，暂停下一次模型调用（包括工具续轮），不暂停已启动的工具；ASR 终态后恢复。此处是对旧设计"不等待 ASR"的明确变更。设置 ASR 超时与错误终态，避免永久阻塞。用户输入在工具调用与对应结果完整落库后加入，不能插入协议要求成对的消息之间。

实时语音打断默认只取消输出；旧模型生成可抑制对外文本，已启动工具继续完成。可取消纯生成是后续可选优化，不能无条件取消整个工具循环。用户明确取消任务时走任务管理接口。

### 4.2 结果可靠性

区分 RECEIVED、CLAIMED、COMMITTED：事件接收后可持久化；选入批次后标记认领；写入会话历史后标记提交。建议 SQLite 事务原子完成历史追加和消费标记。取消发生在提交前则释放认领；提交后不重复追加，若回复未投递，保留待汇报标记供后续运行处理。任务结果作为内部数据而非伪造用户消息；模型投影遵循供应商协议。

回复 ID 与运行 ID 隔离迟到的 TTS、ASR 和工具回调。工具调用 ID 用于执行记录；外部副作用若无幂等接口，结果未知时禁止自动重跑，不能承诺跨系统恰好一次。

## 5. 子会话调度

``` mermaid
flowchart TD
 A[委派请求] --> B{参数和权限有效?}
 B -->|否| X[返回拒绝]
 B -->|是| C[持久化任务并返回受理 ID]
 C --> D{本 Session 空闲且有额度?}
 D -->|否| W[等待释放额度]
 W -.唤醒.-> D
 D -->|是| E[执行任务]
 E --> F[持久化终态与待回投事件]
 F --> G[释放执行额度]
 G --> H[向父会话投递结果]
 H --> I{投递确认?}
 I -->|否| J[重试投递而非重跑任务]
 J --> H
 I -->|是| K[完成]
 G --> D
```

子任务受理返回 child_session_id 与 run_id；同一子会话再次委派沿用 session_id、新建 run_id。子任务执行不读取主会话 VAD、ASR、TTS 状态。主会话打断不级联取消子任务。首版维持现有子会话工具权限，不新增递归委派或工具能力。并发额度可配置，采用 FIFO 准入；终态与回投记录建议同事务写入，回投按 event_id 去重。进程重启时已完成任务只重投结果；执行中任务标记中断或未知，不盲目重跑。

## 6. 接口与实现建议

以下是拟新增接口，不是已核验的源码签名。

``` python
class SchedulingPolicy(Protocol):
    def decide(self, state, pending) -> Decision: ...

class SessionScheduler:
    async def submit(self, event: Event) -> None: ...
    async def serve(self) -> None: ...
```

Decision 可包含 WAIT、START、CONTINUE、STOP_OUTPUT、REQUEST_CANCEL，以及待消费事件 ID。策略为无 I/O 的确定性函数；执行引擎串行更新状态、认领批次并派发异步动作。长耗时操作不得阻塞事件循环，完成后回投事件。控制事件与业务待处理池分离，防止打断被大量结果淹没。语音回调跨线程时通过线程安全入口提交事件。状态更新与批次认领之间不得存在可被其他协程插入的 await；持久化异步完成后需重新校验运行代次及门控状态。

建议代码位置（实施前按仓库实际结构调整）：

  模块                  改造
  --------------------- ----------------------------------------------
  runtime/engine.py     抽离外部队列消费；将安全边界和终态交给调度器
  runtime/subtasks.py   通过统一事件入口回投；任务终态与回投去重
  runtime/scheduler/    通用引擎、事件、状态、两种策略
  speech/               发布话轮、ASR 终态、输出及打断事件
  通道适配器            保留批量输入、输出路由和投递确认
  SQLite 存储           增加最小事件消费及回投记录；迁移测试
  tests/                模拟时钟、模型、工具、ASR、TTS、通道

## 7. 可观测性（首版必做）

结构化日志记录 event_id、session_id、run_id、turn_id、reply_id、事件序号、前后状态、决策、原因码、队列长度、等待时长、错误类型。默认不记录正文、音频、密钥。原因码例如 WAIT_USER_INPUT、WAIT_DELIVERY、WAIT_CAPACITY、START_USER_BATCH、START_BACKGROUND、CONTINUE_TOOL_LOOP。

指标：事件入队到决策耗时、ASR 完成到启动耗时、后台结果等待时长、打断到停播耗时、重复事件数、超时数。使用单调时钟计算耗时。后台等待过久记录告警，但不以超时为由抢话。

  ----------------------- ---------------------------------------------- ---------------------------------------------------

  4                       接入语音与飞书事件                             输入门控、无效 ASR、打断、迟到回调测试通过

  5                       集成、迁移、交付及本地验收                     无密钥模拟全通过；真实 Mac 与供应商接口由用户验收
  --------------------------------------------------------------------------------------------------------------------------

阶段 0 先写失败用例，再修改代码。使用可控 Future、屏障、虚拟时钟，避免依赖 sleep 制造竞争。阶段间保留可运行版本；必要时使用临时配置切换旧调度入口，但不得同时启用两套消费者。

## 9. 验收矩阵

  ID    场景                     预期
  ----- ------------------------ ----------------------------------
  T01   空闲时结果到达           一次主动运行
  T02   说话时结果到达           不启动
  T03   静默判断期间结果到达     不启动
  T04   等待 ASR 时结果到达      不启动
  T05   有效 ASR 返回            用户输入与结果同批进入
  T06   空 ASR                   解除门控并处理结果
  T07   ASR 超时或失败           不死锁，迟到结果不污染新话轮
  T08   多个话轮重叠             旧回调不提前解除门控
  T09   工具运行时结果到达       工具继续，安全边界前不消费
  T10   工具续轮时仍在说话       暂缓下一模型调用，ASR 终态后恢复
  T11   TTS 正在播放             后台结果不抢播
  T12   用户打断 TTS             仅确认前缀入历史，迟到音频丢弃
  T13   结果触发后用户突然开口   抑制旧输出，结果仍可汇报
  T14   多结果同时到达           批量消费，无并发启动
  T15   重复回投                 同事件只入历史一次
  T16   同子会话两次委派         串行且 run_id 不同
  T17   不同子会话并发           在额度内并行，不受主语音状态影响
  T18   子任务完成后回投失败     重投结果，不重跑模型
  T19   工具副作用结果未知       不自动重复执行
  T20   进程重启                 已提交历史保留，未投递结果可恢复
  T21   飞书同批图文输入         顺序和边界不变，只触发一次
  T22   投递失败或超时           正确终态，不无限等待或自动重发
  T23   并发额度耗尽             等待释放，无饥饿
  T24   日志复盘                 可还原事件顺序、状态与决策原因

全部模拟测试无需模型 API Key；真实模型、飞书及 Mac 音频设备留给本地验收。此文档为设计交付，不代表代码已实现或测试已通过。
