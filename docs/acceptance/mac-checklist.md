# 目标 Mac 实机验收清单

用专用飞书对话、合成图片和测试话术。按 [README 的安装与启动说明](../../README.md)准备 Python、lark-cli 和模型权限，密钥只填本机私有配置，不放进验收记录。配置有效的 `agents/main.md` 并启用 `delegate_subtask`，至少添加一个实际子角色以验收委派。先用 `text`，再切 `voice`，最后切回 `text`；从新库开始，三次启动使用同一 `database` 和 CLI 登录账号，不要并行打开第二个进程。真实模型、飞书和设备仍待目标 Mac 实机验收；离线测试通过不等于本清单通过。

## 文字模式

切换到搜索版时配置新数据库路径，保留旧库。确认 CLI 是目标用户身份，并授权 `search:message`、原始批量取正文、下载资源及按 `open_id` 发私聊。

| 编号 | 操作 | 通过判据 |
| --- | --- | --- |
| T1 | 以 `text` 启动；从未与 Agent 互发消息的真人私聊发「记住验收暗号为青石」并在同一个轮询间隔内补发两条编号文本，记录发送和回复时间（超过两个周期仍未回复时，记录搜索耗时和失败状态）。 | 启动不要求虚拟声卡，也不会自动接听来电；CLI 回复能复述暗号，服务同批按原顺序取到编号消息并触发一次运行，没有重复历史，不把自己的消息当输入。 |
| T2 | 发一张合成图片（例如纸上写「方框内是 37」），再发一次同条图文：「读出图片数字，用 `delegate_subtask` 计算其两倍，然后告诉我结果」。 | 单独图片与富文本都可读。分别记录三步：① 同一轮图文触发流式工具调用，以原调用 ID 回传即时受理，只含受理状态和 `agent_id`；② 后台结果带来源 `agent_id`、状态和正文或错误，不含内部运行或委派 ID，不当作即时工具结果；③ 主会话最终回复 `74`。图片和工具分开测不算通过。 |
| T3 | 发一条短语音条说「蓝色风筝」，并发一条普通文字；转写期间让另一真人私聊发普通文字。 | 主会话收到实际转写，CLI 回复能使用转写内容；同批普通文字处理正常，另一用户的普通文字不必等该语音条完成。 |
| T4 | 在专用测试配置中临时把 `[timeouts]` 的 `asr` 调到足够短，以实际触发转写超时，重启后同一轮发语音条加普通文字，之后恢复正常时限。 | 单条失败语音最多一次请求，没有转写输入；原对话收到一次「语音接收失败，请重新发送。」，同批正常消息仍处理，不写入模型历史。不成功复现故障时标未验，不改为已通过。 |
| T5（选用 OpenAI Responses 时） | 让主角色的 `model_id` 引用支持所填推理强度、图文和函数工具的 `[models.llm.<ID>]` 完成 T2。用同一数据库、API Key、`base_url`、`model` 和 `reasoning_effort` 重启，再问合成图片中的数字。 | 工具结果续轮和重启后的请求成功；文字历史只表示回复已生成，不要求已确认送达。按下列三项分别记录，不用答对数字替代密文证据。 |
| T6（有两套模型服务时） | 为主角色和子角色填写不同的 `model_id`，分别引用不同的 Provider。完成一次委派，再复用同一直属子 Agent。 | 分别核对主、子普通请求和工具续轮走各自模型；具备足够历史并触发压缩时，摘要也应走所属角色的模型。验证时只记服务归属和成功状态，不导出请求体。 |

- **私有项入库**：只读检查匹配的已完成助手响应是否存有非空加密推理项；只有私有记录行不算。只记录布尔结果或计数。
- **实际回传**：在本机对实际序列化并交给 HTTP 客户端的请求做仅内存核对，检查工具续轮及重启后的 `input` 是否在对应位置携带同一密文。只记录布尔结果或计数；无法核对或未观察到推理项则记待验，不用入库结果替代。
- **供应商利用**：记录请求状态、耗时与可观察回复。请求成功或模型答对不证明供应商实际利用了密文；没有独立证据时记为未证实。

更换 Key（含同一项目轮换）、地址、模型或推理强度时，既有密文不应出站，但通用历史仍可使用。若验证自定义端点，只将 Key 和模型输入发送到可信的 HTTPS 服务。旧手工标签记录不再使用。

T5 不导出请求体、密文原值、数据库或可读推理摘要，也不要开启会记录原始正文或凭据的抓包／日志。离线验收不覆盖真实 OpenAI、自定义端点或目标 Mac。

## 实时语音模式

| 编号 | 操作 | 通过判据 |
| --- | --- | --- |
| V1 | 按 README 安装 `voice` 依赖、准备 Silero 模型和两台 CoreAudio 虚拟设备。在飞书选择各自扬声器和麦克风，按 README 授予会议读取与桌面权限，切 `voice` 重启，请另一位从未给 Agent 发过文字的联系人直接拨打语音。分别先说一句，再保持安静听完整回答。 | 程序按 `open_id` 核验来电人并直接接通，不等待文字，也不发开场消息；两路设备可打开；对端讲话能转写，对端能听到合成回复；安静时播报不会触发自己的 VAD 或进入 ASR。录入与播放路径无明显串音。 |
| V2 | 说 3 轮简短测试句，每轮停说并等到首段出声。记下停说至对端听到首段回复的秒数。 | 每次完整话轮只提交一次文件转写；收到首段即可播、不等整段回答完成。记录三次延迟及是否满足使用方事先约定的可接受值，无约定则记录实测值、待确认。 |
| V3 | 要求回复持续几秒；听到开头后说「停，改答蓝色」，停说等转写。再试一次在旧回复尚未出声时开口；另核对一次开口时工具已启动的情形，未复现则记待验。 | 旧播报停止，转写结束后也不恢复，已交设备的少量尾音可自然结束。打断后只保留从首段起已完整交给本地设备的连续合成段对应的正文，不按播放时长估算对端听到的字符；首段未确认则记 `ZERO`。非 `FULL` 回执截断仍在生成的本轮模型流，不再启动新工具，也不进入工具续轮；已启动的工具照常完成，其调用和结果落库。新转写由同一主 Runtime 继续处理。 |
| V4 | 接通且未说话时，从飞书私聊发文字、语音条，各验一次。再让一项已受理的子任务在说话或等待实时转写期间完成，使飞书文字、子任务结果、最后一条有效转写依次到达调度器。另试实时转写未得到有效文本的情形，并按 T4 验证飞书语音条超时；未复现的时序或故障记待验，验后恢复配置。 | 文字、成功转写的语音条和子任务结果触发的主会话回复可在通话中播报。话轮或实时转写未结束时不放行暂存输入；最后一条有效转写与空闲一起提交，只交接一批，顺序为「飞书文字 → 子任务结果 → 实时转写」。实时转写为空、失败或超时时，话轮结束后仍能放行暂存输入。飞书语音条失败通知只发到原私聊。 |
| V5 | 手动挂断，保持 `voice` 且不重启，发一条文字。另尝试让后台发送的 CLI 单次调用超时，同时让下一条消息入队；无法复现超时则此项记待验。最后恢复 `text`、重启，发「前面记住的验收暗号是什么？」。 | 挂断后同一主 Runtime 继续处理输入，文字回复先落库、再由后台发送；后台发送超时不阻塞已入队的后续输入，也不视为送达。切回 `text` 后 CLI 返回「青石」，不打开音频设备；同一主 Session 中可查到通话转写与已确认的语音回复，未补发失败或未知投递。 |
| V6 | 在测试配置临时调小 `voice.delivery_timeout`，要求多句长回复并保持安静，确认流式播放跨过总时限；验后恢复配置。 | 到总时限即使仍在播放也结束本条回复，状态为 `UNKNOWN`；历史只保留已完整交给设备的正文前缀。 |
| V7 | 在测试对话中用默认 `voice_text_copy` 各触发一次完整播报和中途打断；随后设为 `false` 并重启，再触发一次播报。 | 默认来电人以自己的 `open_id` 各收到一份与入库确认正文一致的副本；无确认正文时不发，不产生重复历史。关闭副本后语音仍正常，不再发回复副本。 |
| V8 | 分别在回复首次交接前和已交给语音后挂断；再测挂断后立即由同一人重拨、由另一位真人联系人来电，以及响铃撤回、群聊或会议邀请、遮挡和最小化。 | 首次交接时已无有效通话的回复走飞书全文；已交给语音的回复只按旧通话回执结算，不改发全文，开启副本时也只发送已确认且入库的正文。新通话不接收旧通话迟到的转写、输入状态或待播音频；另一人使用自己的主 Session。目标变化或身份不确定时不点击；记录群聊和会议邀请是否意外命中首版筛选条件。仅不可见但仍能跟踪的通话不断开。 |
| V9（空转写唤醒） | 用合成对话、百炼流式 ASR 和兼容模型配置（如示例中关闭思考的 DeepSeek），开启 DEBUG 日志。听到旧回复出声后咳嗽打断，保持通话并等语音空闲，不发新消息。核对旧回复同一 `reply=` 有 `voice playback interrupted` 且 `first_pcm_to_output_ms` 有数值；同一 `turn=` 有 `voice turn endpoint detected` 和 `reason=asr_empty_transcript phase=finish`。另测暂存文字：在该话轮中发合成飞书文字，确认同会话在空转写结算前已收到且尚待处理。另试有效转写、未开播、超时、采集丢帧和挂断。 | 正例无其他待处理输入，旧回复 `reply committed` 后只出现一个新运行的模型首请求（`model request started` 的 `run=` 不同于旧运行）；历史无新增输入条目，私聊无空转写回显，旧音频不续播，不要求模型接着说。暂存文字反例在 ASR 结算后只启动一轮处理该文字批次，不插入额外唤醒；其余反例也不额外唤醒。缺少明确空转写证据或未复现记待验，不能以没看到转写代替。 |

## 子任务回投：忙和闲各验一次

| 编号 | 操作 | 通过判据 |
| --- | --- | --- |
| S1 | 委派一项需一些时间的合成撰写任务，要求主会话先简短告知已受理；在任务完成前再次发文字要求较长回答，让主会话在结果回来时仍有回复在生成或投递。 | 主会话先处理新输入；子任务完成与入队发生在该回复收尾前，结果只在下一处安全边界纳入，不插入本轮工具调用块或打断投递。若时序没重合，重做而不是判通过。 |
| S2 | 再委派一项任务；看到受理后不发任何新消息，并让主会话先空闲。 | 完成后无需新输入，回投独立唤醒主会话并收到结果。两场景分别核对模型可见的 `agent_id`，及 SQLite 内部的 `delegation_id`、实际 `run_id`、完成及入队时间。子 Agent 的最终回复只交给直属父级，不单独对外发送。 |

历史和回执可在本机用只读方式核对 `messages`、`reply_outcomes`、`delegations`、`agent_runs`。文字回执的 `FULL` 只表示通道收齐全文，不表示 CLI 发送成功或对端收到；完整回复落库后才由 CLI 在后台尝试发送，CLI 超时表示发送结果未知。语音回执的 `FULL` 只表示本地已完整确认，不能据此断定对端确实听见。`reply_enqueued_at` 仅表示入队，不证明主会话已消费。不要上传历史库或原始日志。记录格式：`编号 | 模式与版本（macOS/Python/CLI） | 通过/失败/待验 | 简短重现步骤 | 预期与实际 | 耗时或脱敏证据`。对外记录仅留合成话术、状态、时长和经脱敏的关联 ID；删去密钥、会话登录材料、用户标识、私人消息、设备录音和绝对个人路径。
