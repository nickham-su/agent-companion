# 会话调度器重构方案

本方案面向 `v0.1`。调度器统一接收会话输入并决定何时放行。Runtime 继续负责入队后的串行执行、工具续轮和安全边界。通道层根据实际连接选择回复方式，并处理语音播放、停播和投递结果。

## 每个会话一个调度器

- 调度器是按会话 ID 归属的组件，由应用的内存映射表管理活跃实例。主会话和子会话共用 Runtime 的输入和输出接口。会话记录和历史按需查库。
- 调度器创建时绑定模型输出的投递实现。主会话的输出目标是用户，由面向用户的投递实现交给通道层。子会话的输出目标是父会话，由面向会话的投递实现把完整任务结果作为新输入交给父会话调度器。

### 实例创建

有效的新事件需要调度器处理时，统一投递入口按会话 ID 查表，有实例就复用，没有就创建并登记。查找与登记作为同一步完成，同一会话同时只使用一个实例。飞书消息、子任务回投和确认接通的通话都可以触发创建。

### 实例清理

会话管理方在以下条件都满足时，从内存映射表移除调度器。

- 当前没有有效通话，相关话轮和转写均已收尾。
- 待放行队列为空，依赖该实例的在途交接已结束。
- Runtime 已回到空闲。它自己的队列已清空，模型、工具和投递回执都已完成结算。回执超时也按原有规则收尾。

通话结束、最后一个话轮或转写收尾、批次交接完成、在途操作结束或 Runtime 结束时，可以触发清理检查。会话管理方读取 Runtime 的当前状态，在同一步检查条件并移除实例。Runtime 状态用于实例清理，调度器按会话输入状态决定消息放行。

仍在执行的子任务可以在完成后按父会话 ID 回投。父会话的调度器已经回收时，由统一投递入口重新创建。

## 会话事件

事件名统一用小写字母和下划线。

| 事件名 | 触发时点和用途 |
| --- | --- |
| `session_input` | 会话收到消息内容、输入状态变化，或同时收到两者。由调度器处理。 |
| `call_started` | 通道层确认通话接通。会话管理方查找或创建调度器。 |
| `call_ended` | 通道层解除通话绑定。会话管理方检查清理条件。 |
| `runtime_started` | Runtime 从空闲进入运行，开始处理队列。 |
| `runtime_ended` | Runtime 清空队列并完成结算，重新回到空闲。会话管理方检查清理条件。 |

回复对象和最终回执沿投递接口交接。

## 输入状态和放行

用户输入、子任务回投和其他外部会话消息都先进入目标会话的调度器。主会话调度器保存语音层提供的「输入中／空闲」状态和待放行的消息。用户开口、等待话轮结束和等待转写都属于「输入中」。语音层确认所有实时话轮都已结束后，报告「空闲」。

`session_input` 可以携带内容、状态变化，或同时携带两者。调度器按会话串行处理事件，把接收内容、更新状态和决定是否交接作为同一步完成。处理后处于「空闲」且队列有消息时，交接一个批次。处于「输入中」时，消息继续暂存。

- **只带内容。** 用户正在说话时补发飞书文字或图片，这些内容进入调度器的待放行队列，语音输入状态保持「输入中」。这期间到达的子任务结果同样暂存。
- **同时带内容和状态变化。** 最后一个待结束的语音话轮有有效转写时，语音层在同一事件中交付转写文本和切到「空闲」的信号。调度器追加转写并切换状态，把待放行消息作为一个批次交给 Runtime。其他事件只能在这个处理步骤之前或之后进入，避免后台结果抢在转写之前单独入队。
- **只带状态变化。** 语音层可以在确认开口时报告「输入中」，也可以在空转写、失败或超时收尾后报告「空闲」。切到「空闲」时，有待放行消息就整批交给 Runtime。队列为空时保持空闲。

同一批次保持待放行队列的顺序和消息内容。放行依据会话的输入状态，`session_input` 暂不增加通用来源或优先级字段。子会话的任务通过原有准入后，由子会话调度器直接放行。

### 异步工具结果

子任务结果和其他异步工具结果使用统一信封。掌握原始调用信息的结果生产方负责组装。头部可带触发工具名和工具调用 ID 等元信息，正文放结果。

信封作为 `session_input` 的消息内容投递，调度器按同一套规则暂存和放行。Runtime 根据结构识别内部结果，关联到原工具调用，并在发送给模型时保留这层语义。委派工具的即时受理回复照常结算，子任务完成后的结果作为一条新的内部输入回投。

## Runtime 入队、执行与输出

入队是调度器与 Runtime 的交接点。Runtime 沿用现有队列机制，空闲时自行启动，运行中在原有安全边界判断已入队的消息应纳入工具续轮，还是留给下一次运行。调度器的放行策略作用于尚未交接的输入。实时收音可以和 Runtime 正在执行的任务并行，当前运行的同步工具结果沿用原有落库和续轮规则。

Runtime 通过本会话的调度器交付模型文本。纯文本回复与同一模型响应中伴随工具调用的文本共用输出接口，工具调用及其结果仍由 Runtime 处理。

- **主会话面向用户的输出。** 统一以回复流进入投递接口。通道层在回复交接时选择实际投递方式和对应的确认语义。
- **子会话面向父会话的输出。** 固定按全文交付。Runtime 收齐文本并写入子会话历史，任务到达终态后，完整结果一次回投给父会话。父会话再向用户回复时，按自身的用户投递规则处理。

Runtime 交付流式回复或全文时，底层模型均可沿用现有的流式调用。

## 通道选择和文字交接回执

通道层维护接通状态，在回复交接时根据用户的实际连接选择电话或飞书文字。电话接通时，即使本轮输入是用户从飞书补发的链接、图片或语音条，或者由子任务结果触发，生成的回复也可以在当前电话里流式播报。回复交接时没有有效通话，就走全文发送。

- **语音交付。** 通道边收边播。Runtime 按播放回执确认的正文入库。已经开始播报后挂断的回复，按原通话已确认的播放前缀结算。
- **全文交付。** 飞书文字投递端收齐全文后返回「已收齐」的交接回执。Runtime 确认模型响应完整并完成历史提交后，通道将全文交给后台发送队列。飞书 CLI 的实际发送结果由通道层结算。CLI 超时表示结果未知，Runtime 可以继续处理后续输入。

接通状态的读取方式、回复交接接口和全文落库后的发送通知在实施前确认。全文交付可以复用 Runtime 已收集的正文。

## 流式回复和播放回执

调度器将 Runtime 创建的同一个回复对象交给实时语音层。Runtime 写入文本，语音层读取并播放。语音层维护播放进度并在回复对象上提供查询入口，Runtime 等待回执时可以通过同一个对象查询。播放结束或停播时，最终回执经调度器交回 Runtime。

## 两处打断和历史结算

- **交给实时语音层之前。** 调度器准备转发语音回复时，如果用户已处于「输入中」，调度器直接向 Runtime 返回零投递。用户处于「空闲」时正常转发回复对象。
- **交给实时语音层之后。** 语音层检测到用户开口时，沿用现有的停播、清理待播内容和确认已播前缀的机制，并返回最终回执。

用户开口导致本轮文本被拦下或打断时，Runtime 截断仍在进行的模型流。已经启动的工具照常完成，工具调用和对应结果一同落库。本次运行在安全边界结束，Runtime 随后处理已入队的新输入。纯工具轮照常推进。

纯文本回复零投递时，模型可见的历史略过该空回复。部分投递只保留回执确认的正文前缀。带工具调用的回复即使正文为空，工具调用和对应结果也完整保留。下一轮使用已有上下文和新的用户输入，正文里不追加打断标记，也不另设待汇报标记。

## 验证场景

- 同一会话的多个新事件同时到达时只创建一个调度器。调度器交出最后一批消息后，如果 Runtime 仍在运行或等回执，保留实例。Runtime 结束且其他条件满足后清理，随后到达的子任务结果可以按会话 ID 重建实例。
- 异步工具结果携带原调用信息，以 `session_input` 投递。调度器按输入状态放行，Runtime 在读取内容时识别结果并关联原调用。
- 用户说话时同时收到飞书消息和子任务结果。调度器等到语音输入结束，只交接一次批次。空转写、失败或超时后，队列中已有的消息仍可放行。
- Runtime 正处于工具执行或续轮时收到已放行输入，仍在原有安全边界处理。同一会话串行，子任务按原有准入规则推进。
- 通话接通时，飞书补充材料触发的回复在电话里播报。回复交接前已挂断时，收齐全文并在落库后通过飞书后台发送。CLI 超时只影响通道的发送结果。
- 转发前处于「输入中」时返回零投递。转发后用户开口时，语音层返回已播前缀。两种情况下若已有工具启动，工具调用和对应结果都完整结算。
