# agent-companion

飞书多模态 Agent 首版，提供共享历史、异步委派、飞书文字／图文／语音条与 Mac 实时语音。离线验收不接入真实飞书、模型账号或设备。

## 目录与依赖方向

路径相对于 `src/agent_companion/`：

| 路径 | 职责 | 状态 |
|---|---|---|
| `__main__.py`、`app.py`、`config.py` | 程序组装、启动与配置 | 已实现 |
| `protocol.py` | 模型、通道与消息的共同契约 | 已实现 |
| `runtime/engine.py`、`runtime/context.py`、`runtime/tools.py` | 运行编排、上下文投影与工具注册 | 已实现 |
| `storage/sqlite.py`、`models/` | SQLite 历史存储、DeepSeek 和 OpenAI Responses LLM 适配 | 离线模拟通过，真实调用待验 |
| `runtime/subtasks.py` | 异步委派与结果回投 | 已实现 |
| `channels/feishu/` | CLI、轮询、消息解析与通道路由 | 两种模式保留飞书输入，待实机验收 |
| `speech/` | 与 IM 无关的文件 ASR、VAD、TTS 和实时语音调度 | 离线模拟通过，待实机验收 |
| `channels/audio/` | macOS CoreAudio 双路音频设备 | 离线替身验证，待实机验收 |

模型与通道实现由启动入口按 `protocol.py` 中的契约注入；Runtime 不导入具体模型、飞书或语音实现。SQLite 存储使用共同消息类型，不反向依赖 Runtime。

## 运行离线验收

需要 Python 3.11+ 和启用了 FTS5 的 SQLite（使用 Python 自带 `sqlite3`）。在仓库根目录执行：

```sh
python -m venv .venv
.venv/bin/python -m pip install .
.venv/bin/python -m unittest discover -s tests -v
```

`pip install .` 会一次安装文字和语音模式的 Python 依赖，无需另装 `.[voice]`。安装需要有适配当前 Python 版本和架构的 `onnxruntime` 安装包。Intel Mac 建议用 Python 3.12，Apple 芯片的 Mac 建议用原生 `arm64` Python。

最后一条是统一离线验收入口：不需要模型密钥、飞书登录或音频设备；集成用例使用项目内临时 SQLite，结束后清理。安装依赖若不能访问公开索引，可从准备好的本地 wheel 目录安装：`.venv/bin/python -m pip install --no-index --find-links <wheel目录> .`（还需包含 `pyproject.toml` 的构建依赖）。精简环境若缺 `ensurepip`，需先提供带 pip 的虚拟环境；目标 Mac 建议使用完整的 Python 发行版。

`.venv/bin/python -m agent_companion` 和 `.venv/bin/python -m agent_companion --demo-subtasks` 可单独运行两个简短演示；不需要生产 Provider 或密钥，始终使用内存数据库和内置角色，不需要 `agents/main.md`，不等同于全量验收。可传 `--config config.example.toml` 验证其他模拟配置；只有 `--run` 使用配置中的数据库路径和 Provider。

## 运行日志

应用日志只写标准输出，不创建日志文件。在配置顶层设置 `log_level`，修改后重启。默认 `WARNING`，只显示警告和错误，同模块同类警告每 30 秒最多打印一次；`INFO` 另显示启停，`ERROR` 和 `CRITICAL` 可进一步收紧输出。启动配置错误写到标准错误，不受日志级别影响。

排查时改为 `log_level = "DEBUG"`。用 `run` 和 `reply` ID 串起输入、模型、工具与投递；另外记录上下文压缩、子任务和实时语音的阶段状态。日志只有计数、耗时、状态等诊断信息，不包含消息正文、语音转写、工具参数、原始请求或密钥；不逐 token、逐音频帧或逐空轮询输出。

## 选择 Provider

正式启动通过顶层 `llm_provider`、`asr_provider` 引用 `[providers.<名字>]`；`voice` 还需 `tts_provider`，`text` 不使用它。名字是任意配置 ID，`adapter` 才是实际适配器。每套 Provider 在本机配置中直接填写 `api_key`，不从环境变量读取；未选用的 Provider 不需要密钥。改引用后重启即可切换。

旧的 `[llm]`、`[deepseek]`、`[minimax]` 及旧语音模型字段不再兼容，请按 [config.example.toml](config.example.toml) 迁移。`adapter` 必须显式指定，`.llm.reasoning_effort` 必填。

请求时限统一配置在 `[timeouts]`，单位秒：`llm` 是单次模型请求总时限（默认 60），`asr` 是单次转写总时限（默认 30），`tts` 是单次网络读写及等待响应的时限（默认 25，仅 `voice` 启用）。切换 Provider 不改变这些值。旧的 `runtime.model_timeout` 和 Provider 能力表里的 `timeout` 不再兼容；语音投递与飞书 CLI 的时限独立配置。升级时删除 `[runtime]` 中旧的 `delivery_timeout`。

| `adapter` | 配置 |
| --- | --- |
| `deepseek` | `.llm.model` 可省略，默认 `deepseek-flash`。`reasoning_effort = "disabled"` 显式关闭思考；其他值由所选模型解释。历史切到思考开启时，如有不兼容旧记录，用摘要承接，原文仍可查。 |
| `openai_responses` | `.llm.model` 必填。可选 Provider 层 `base_url`，默认 `https://api.openai.com/v1`，请求时在其后追加 `/responses`。`reasoning_effort` 原样传给 Responses，例如 `low`，或选用明确支持 `none` 的模型来关闭推理。 |
| `minimax` | Provider 层 `region` 选 `cn`（默认）或 `global`。`.asr.model` 默认 `asr-1.0`，也可填写其他兼容同一文件转写接口的模型名；`.asr.max_audio_seconds` 必填，无默认值。`.tts` 配置模型和音色。ASR、TTS 可以共用一套 Provider，也可以分别使用不同区域和 Key。 |

升级旧配置时，删除 `[voice]` 的 `max_turn_seconds`，在 `asr_provider` 选中的 `[providers.<名称>.asr]` 中明确设置 `max_audio_seconds`（有限正数，单位为秒）。正式的 `text` 和 `voice` 模式都要填写；示例中的 `500` 是 `asr-1.0` 的参考值，使用其他模型时请按其接口限制填写。

**只配置可信的 HTTPS 地址**：自定义服务会收到所选 Provider 的 API Key 和发送给模型的输入。地址不要包含凭据、查询参数或片段；客户端不跟随重定向。其他适配器不支持 `base_url`。

Responses 请求设置 `store: false` 并显式请求加密推理项，不使用 `previous_response_id`，也不主动请求可读推理摘要。请求正常完成后原样保存有效密文，之后只在原作用域（同一适配器、端点、模型、凭据与推理档位）按原生项顺序回传；压缩请求也遵守此规则。可读摘要若随协议返回，只作为私有回传字段，不是需要概括的内容。SQLite 中的私有回传记录与回复、工具结果和回执原子提交，客户端不主动把结构化私有协议字段写入正文、搜索、日志或会话摘要。不要共享历史数据库或提取并分享私有记录。

本地用数据库级随机盐、API Key、规范化后的 `base_url` 和 `model` 自动生成指纹，Provider 名字不参与计算。更换 Key（包括同一项目轮换）、地址、模型或 `reasoning_effort` 后，不回传不匹配的密文，但仍可使用通用聊天历史。旧手工标签下的回传记录不再读取，原数据库与通用历史保留。

工具定义和请求前缀变化不阻止回传；续轮仍按实际输入用量触发压缩，已纳入摘要的私有记录不再加载。语音零投递或部分投递不回传未确认正文，保留其他有效推理项及配对的工具调用和结果。私有记录缺失或损坏时可使用通用历史；供应商是否利用密文由其决定。服务端拒绝时结束当前请求，不自动重试、切换供应商或重跑工具。按 [Mac 实机验收清单](docs/acceptance/mac-checklist.md)分别核对私有项入库、出站携带和供应商实际利用。

## 本机启动飞书文字模式

1. 用专用飞书账号在本机完成 CLI **用户身份**登录。需要支持 [`im +chat-list --types p2p`](https://github.com/larksuite/cli/blob/main/skills/lark-im/references/lark-im-chat-list.md) 的 CLI 版本和 `im:chat:read` 权限，并确认已授权查询当前登录用户信息（`GET /open-apis/authen/v1/user_info`）、[读取私聊历史](https://open.feishu.cn/document/server-docs/im-v1/message/list)、下载媒体和发送消息。程序不会发起登录或直接读取凭据文件。运行中不要切换 CLI 登录账号或应用配置。
2. 复制 `config.example.toml` 为 `config.local.toml`，启用 `[feishu]`，使用默认的 `mode = "text"`。如果旧配置有 `own_open_id`，请删除这一行。`database` 可指向尚不存在的新文件，首次启动会创建它并绑定当前 CLI 登录账号，请先确认登录的是专用账号。文字模式不加载音频设备或 TTS，也不监听来电、不查询会议；`cli_timeout` 限制单次飞书 CLI 调用（默认 20 秒）。
3. 按[选择 Provider](#选择-provider)填好所选 LLM 和 MiniMax ASR 的 `api_key`；只在本机私有配置填写真实 Key，不要分享或提交该文件。MiniMax 区域按账号选择 `cn`（[国内 API](https://platform.minimax.cn/docs/api-reference/speech-to-text)）或 `global`（[国际 API](https://platform.minimax.io/docs/api-reference/speech-to-text)）。工作目录需要允许建立用于资源下载的短期目录。
4. 在启动工作目录下复制 `agents/main.example.md` 为 `agents/main.md`，并按 [Agent 角色配置](#agent-角色配置)编辑。需要委派时，再从 `agents/sub.example.md` 创建实际子角色。

```sh
.venv/bin/python -m agent_companion --run --config config.local.toml
```

多私聊模式不设白名单，依赖飞书自身的访问边界。只接受真人的一对一私聊，忽略群聊、机器人和自己的消息。首次收到合格消息或处理来电时，按联系人的 `open_id` 定位独立主 Agent；后续复用它绑定的 Session 历史，并向原私聊回复。同一用户串行，不同用户可并行；没有新增每人限频或全局并发限制。只处理数据库首次启用后发出的消息，即使该私聊稍晚才被发现；重启不会重设这个基准。

启动时先校验角色文件，再查询一次 CLI 登录账号，用查到的身份校验已有数据库归属或绑定空库。查不到账号或账号与已有库不匹配时拒绝启动；核验期间的新消息也纳入首次扫描。只有完整、每条记录都能明确分类的快照才能停用路由。无效的 `chat_id`、无法判定对话类型，或真人私聊的对端 `open_id` 缺失或无效，都会使整轮发现失败并保留旧路由。明确是群聊、话题群、机器人或自身的记录仍会排除对应路由。只有同一私聊与同一对端重新验证通过，才从原水位及待处理批次恢复。

多私聊轮询遇 SQLite 暂时锁冲突时保留尚未提交的窗口，下轮重试。运行中，关键上下文及子任务结果读取只重试遇锁的查询，输入移交、内部回投入历史、回复归档和子任务状态写入只重试遇锁的事务。不阻塞事件循环，也不重跑模型、工具或发送。后续输入不会越过正在等待的输入；停用路由会取消等待，不补发已取消的回复。

同一 CLI 用户可使用同一个数据库在 `text` 和 `voice` 间切换；更换账号请使用新库。删除 `own_open_id` 不改变数据库格式，已有的兼容数据库可继续使用。不兼容的旧格式需另建新库，程序不会清空旧库。

轮询使用用户身份调用原始 `/open-apis/im/v1/messages`，保留 `body.content`、发送者和媒体键；每个对话约每 10 秒扫描一次，单次最多 200 页，未读完时从下一页继续同一个固定时间窗口，不提前入队或推进水位。取齐后按原时间顺序提交一个批次。累计窗口超过状态上限时尝试缩短时间范围重新读取；即使最小可推进范围也超限则报错，不跳过数据。后续查询回看 10 秒并以消息 ID 去重，重启从持久化水位重读未完成窗口。水位、去重和待接收输入在同一事务保存，已接收但尚未进入历史的批次重启后继续移交；用户输入进入历史后不自动重跑未完成的模型或外发操作。一个数据库由一个实例运行，不复制 SQLite 文件到交付包。离线测试使用模拟 CLI、模型与合成音频，真实协议和权限待本机验收。

每个新窗口默认每页 50 条。列表 CLI 标准输出超过 4 MiB 时，将页大小减半（最低 1 条），丢弃该窗口未提交的消息及游标，下次轮询从同一时间窗口的第一页重读。每页仅 1 条仍超限时报告 `cli_single_result_output_limit`，不提交部分结果、不推进水位，也不跳过消息。

图片按文件头识别（JPEG、PNG、GIF、WebP；单张本机上限 8 MiB）；语音条下载后验证容器和 50 MB 文件上限，提交一次完整文件，不做截断。WAV 超过 `max_audio_seconds` 时在本机拒绝；非 WAV 时长仍由服务端检查。飞书入口按原处理顺序执行现有单图和同批媒体限额，受限图片用文字占位，不挤掉同批可用文本；不会为了找更新的图片突破下载限额。macOS/Linux 的 CLI 下载子进程在写文件前已设置相应文件大小硬上限。富文本链接保留为普通文字，不发起下载。语音条失败或超时不重试，原对话尝试发送一次「语音接收失败，请重新发送。」，通知不走模型、不阻塞同批成功输入，崩溃后不补发。

飞书语音条和实时通话的有效转写会另发到原私聊，仅将原文加粗。用户可以用普通文字或语音补充纠正；模型不等待回显或确认，既有回复和 `voice_text_copy` 不变。回显不额外写入会话历史，使用独立的有界后台队列，与回复的先后顺序不保证；超限、发送失败或关闭时不重试，重启不补发。

文字回执的 `FULL` 只表示通道收齐全文，不表示 CLI 发送成功或对端收到。文字回复成功生成后，先将完整正文与对应工具结果落库，再进入通道的内存队列，由后台任务按顺序调用 CLI 尝试发送。Runtime 不等待 CLI；CLI 超时表示发送结果未知。队列最多 8 条待发，另有最多 1 条发送中；满时丢弃新回复，发送失败只记日志，不重试。关闭时丢弃待发并取消当前发送，不等待队列排空；重启不会补发。

如果在轮询批次落库前进程中断，下次会重新查询窗口；未落库的内容可能重新下载或转写。此时没有已接受的输入或失败通知需要恢复。命令兼容性还依赖于 [raw API 的 `--data -` stdin 支持](https://github.com/larksuite/cli/blob/v1.0.100/cmd/api/api.go)与[资源下载快捷命令](https://github.com/larksuite/cli/blob/v1.0.100/skills/lark-im/references/lark-im-messages-resources-download.md)。

## 本机启动飞书实时语音

**MVP，目标 Mac 待验。** `mode = "voice"` 会监听并自动接听符合条件的来电，同时照常处理私聊文字；不想自动接听时切回 `text`。

### 本机启用飞书自动接听

1. 在目标 Mac 上安装本机虚拟音频驱动，准备**两台不同的 CoreAudio 虚拟设备**。飞书扬声器设为「飞书 → Agent」设备，程序读取该设备；程序把播报写到「Agent → 飞书」设备，飞书麦克风从后一设备读取。不要把两条线路接到同一设备；按 macOS 提示授予启动程序的终端/应用音频输入权限。
2. 按[安装说明](#运行离线验收)在目标 Mac 的虚拟环境安装项目，再查询设备名称和索引（命令不启动 Agent）：

   ```sh
   .venv/bin/python -m sounddevice
   ```

3. 从 [Silero VAD 官方源码](https://github.com/snakers4/silero-vad/blob/master/src/silero_vad/data/silero_vad.onnx)单独取得 `silero_vad.onnx`（使用带 `input/state/sr` 接口的 v6 系列模型，不选只支持其他输入形状的变体），放在本机配置指定路径。程序只加载已有文件，不下载模型，不需要 PyTorch；相对路径以 TOML 文件所在目录为准。音频和 ONNX 依赖不在 `text` 或模拟模式下加载。
4. 沿用[文字模式](#本机启动飞书文字模式)的 CLI 登录和私聊权限，另给同一 CLI 用户授权 `vc:meeting.meetingevent:read`（获取会议信息）；飞书桌面客户端与 CLI 必须登录同一用户，运行中不要切换。检查 `tts_provider` 选中的 MiniMax 配置含 `.tts` 配置表和 `api_key`，并按示例填写 `[voice]` 的设备与 VAD 模型路径。
5. 在目标 Mac 的图形桌面中设置 `[feishu].mode = "voice"`，以同一 `--run --config config.local.toml` 命令启动。可沿用同一账号的库，也可以直接用新库，不需要先运行 `text`。为运行程序的终端或应用授予发送鼠标事件和收音的权限；如系统不提供通话窗口标题，也需授予屏幕录制权限并重启应用。自动接听会移动鼠标，测试时不要同时参加其他通话。

程序为本次来电准备设备时检查两路是否支持所需流格式。输入为 16 kHz 单声道有符号 16-bit PCM（512 样本一帧），直接供 Silero 和 WAV 文件转写使用。输出为 MiniMax 相同采样率的单声道 16-bit PCM，默认 44.1 kHz，可配 16/24/32/44.1 kHz。CoreAudio 在需要且支持时转换设备格式，程序不更改设备全局采样率、不再做第二次重采样。若报 `voice_input_pcm_16khz_mono_not_supported` 或 `voice_output_pcm_rate_or_channels_not_supported`，在「音频 MIDI 设置」和 `sounddevice` 列表核对两条线路；输出可选一个双方支持的采样率，输入需选择能提供 16 kHz 单声道流的设备或系统转换。若通话对端无声，核对虚拟设备首个单声道的路由、飞书麦克风/扬声器选项和设备权限。

输出采样率由 `[voice]` 中的 `output_sample_rate` 设置，单位为 Hz。升级旧配置时，把 `playback_rate` 改为 `output_sample_rate`，数值不变。

VAD 默认连续 3 个 32 ms 人声窗口触发打断，默认静默 1 秒结束话轮。实时录音按实际样本数计时（含预录和已录停顿），以 `max_audio_seconds` 和含 WAV 文件头的 50 MB 字节保护中先到的上限为准。达到上限时立即将保留的前段送入转写队列，不等用户停下。后续声音不再录音，只用于检测静默；达到 `silence_seconds` 前仍算「输入中」，不放行暂存输入，也不开始播报。ASR 仍串行处理，队列满时仍丢弃新录音；空转写、识别失败或超时不会提交转写文本，也不发送飞书语音条式失败通知。话轮和转写均已结束时，即使没有有效文本也会放行暂存输入。

**可选：实时语音提前分段转写。** 在 `[voice]` 中设置 `segment_pause_seconds = 0.4`，`silence_seconds` 可继续用 `1`。两个阈值均向上取整为 32 毫秒帧，短停顿必须比话轮结束早至少一帧。不填写 `segment_pause_seconds` 就走上面的整段逻辑；需要回退时，注释掉该配置并重启。飞书语音条的转写不受影响。

- 已录到当前未转写段满 10 秒，且遇到短停顿时，如果 ASR 空闲，就提前转写这一段。没有停顿不强切；忙时续录，同一次停顿只尝试一次。切段不重置静默计时或本轮累计录音长度。
- 提前转写成功的音频不重传；失败则保留音频，下次短停顿（无需再满 10 秒）或最终停口时与后续未识别音频一起补交。ASR 仍串行；停口时如前段仍在途，等其结果再决定尾段要发哪些音频。没有新语音且前段成功时，不单独提交静音尾段。
- 只有长停顿结束且整轮识别成功，才按顺序合并文本、一次性交付。最终转写失败或超时、无法启动、或录音中采集缺帧，都不交付残缺文本。仅本轮提前请求超时并仍占用 ASR 时，最终补交才额外等待最多一个 ASR 时限。其他话轮若在这段额外等待中结束，且旧请求仍未退出，则跳过转写；正常情况下仍按顺序排队，到轮次时才检查 ASR 是否空闲，不为其他话轮的请求额外等待。挂断和设备故障也不放行未交付话轮。
- 每轮录音上限不因分段或补交而增加。启用分段时，封顶只停止录音；仍须满足 10 秒加可信短停顿（补交免 10 秒）才可提前提交，否则等长停顿后提交。封顶后采集缺帧会重置静默计时，但保留此前已录的音频；提前提交失败仍有最终补交机会。未启用分段时，封顶立即提交的行为不变。

若 `max_audio_seconds` 短到放不下一个 16 kHz 采样点，本次无法准备实时语音，并报告 `voice_asr_max_audio_seconds_below_one_sample`。

语音回复按中英文句号、问号、感叹号或换行切段，逗号和分号不切。每条回复首句不设最短长度；后续累计至少 30 个非空白、非标点字符才在句尾切段。单段达到 200 字符（含空白和标点）时强制切段；首段强切后也按后续规则处理。回复结束时发送剩余正文。空白或纯标点不单独请求合成，也不占用首句。

MiniMax TTS 用 [`/v1/t2a_v2` HTTP SSE](https://platform.minimax.cn/docs/api-reference/speech-t2a-http)逐段发送，首块到达即可播放；每段流结束且待播放低于 `prefetch_seconds` 时才提交下一段。从语音通道开始处理起，`voice.delivery_timeout`（默认 600 秒）是不可续期的总上限。模型输出结束后，Runtime 启动 `voice.idle_timeout`（默认 30 秒）；只有设备实际取走本条回复的 PCM 才续期，补静音或只在合成不算。任一时限到期，投递记为 `UNKNOWN`，历史只保留已确认的连续完整段落，不估算半句。空闲超时由 Runtime 取消投递任务，不等清理或迟到回执。已确认的正文仍进入后续会话历史，不代表对端一定听到了。

如果本机的 `[voice]` 仍显式使用旧示例的 `delivery_timeout = 90`，可改为 `600` 或删除这行使用新默认值。

通话中若设备流断开、采集停滞或 VAD 推理出错，程序会记日志、解除本通语音绑定并停止收音和播报：丢弃尚未提交的录音，取消在途实时转写并忽略迟到结果，不等待清理。已交给语音的回复仍按原回执结算；主 Runtime 继续处理放行的输入，私聊消息轮询、语音条转写和文字回复继续运行。程序不会替你挂断飞书通话，也不会把已交语音的回复改用文字发送或自动重连设备；排查后可再试下一通。

MiniMax 流式合成也可能以 HTTP 200 返回 JSON 业务错误而不是 SSE。该响应最多读取 64 KiB，受 `timeouts.tts` 限制；适配器使用固定错误码分类，不输出响应正文。

### 来电筛选与验收

首版按当前版本实测特征判断：没有会议主窗口且发现唯一来电浮窗时，先准备并打开静音的双路音频，再通过 CLI 查一次活跃会议列表和详情。只有唯一活跃会议在响铃、唯一参会人与非本人的主持人相同、此人的真人私聊会话能立即绑定，且本轮浮窗仍可点击，才会接听。没有接听前总时限，单次 CLI 调用仍有超时，查询结果只用于随后 0.5 秒内的点击。此规则**不证明**邀请一定来自私聊，也无法识别查询结束后、点击前复用同一浮窗的换人来电。

点击后最多等 10 秒；同一飞书会议进程只要新出现一个符合会议窗口特征、不是来电浮窗的窗口，就确认接通。不要求窗口唯一，不限制尺寸，也不必等浮窗消失。接通确认前不转写、不播报。点击失败、设备失活或确认超时会清理本轮音频并回到轮询。原浮窗和新浮窗都按下一轮的查询结果重新判断；程序不会替你挂断已接通的飞书通话。

语音和文字共用该联系人的主 Session。用户说话或等待实时转写时，暂存到达的飞书消息和子任务结果；最后一条有效转写与空闲状态一起提交，转写追加到队尾，整批按到达调度器的顺序放行。子任务结果按主会话回投，不绑定原通话。

回复在首次交接时按有效连接选一次通道。接通时，飞书文字和子任务结果触发的回复也可流式播报；当时没有有效通话则走飞书文字，全文落库后由后台发送，CLI 超时只表示发送结果未知，不阻塞 Runtime。用户开口时，待交付的语音回复被拦截，正在播放的回复会停止；非 `FULL` 语音回执只结束本轮，截断仍在进行的模型流，不再启动新工具或进入工具续轮，已启动的工具照常结算。

接通确认时记录同一进程的全部候选窗口；这些窗口都消失或查询失败时停收停播，只关闭其中一个或仅隐藏窗口不会断开。挂断不关闭主 Runtime；已交给语音的回复仍按原通话回执结算，即使没播也不改发全文或转到下一通。`voice_text_copy` 默认开启，仅把按原回执确认并已归档的正文（可能只是前缀）发给原私聊，不表示对端已听见，也不是失败回退；副本使用原私聊的后台队列，不重试，也不另写一条历史；设为 `false` 可关闭副本。

手工验收：让有私聊的联系人先发文字再从私聊拨号（新库可直接先拨号再发文字），检查同一 Session 和双向音频；通话中验证文字和子任务结果可触发播报，并检查打断、暂存顺序和挂断前后选路。挂断后马上重拨或由另一联系人来电，确认新通话没有上一通的转写或待播音频。另测来电撤回、最小化／遮挡／切桌面和群聊／会议邀请。具体判据见 [Mac 实机验收清单](docs/acceptance/mac-checklist.md#实时语音模式)；目标 Mac 仍待实机验证，离线测试不替代这些步骤。

## Agent 角色配置

正式启动时，只从进程启动工作目录的 `agents/` 加载顶层 UTF-8 `.md` 文件，不跟随符号链接，不读取旧 `AGENTS.md`。必须有通过校验的 `agents/main.md`，否则启动失败。仓库和部署包只提供 `main.example.md` 和 `sub.example.md`；`*.example.md` 不加载。本机实际角色文件由 Git 忽略。配置修改后重启生效。

- `main.md` 是主角色。要添加子角色，将 `sub.example.md` 复制为 `review.md` 等实际文件；去掉 `.md` 的文件名就是角色 ID。
- 每个文件开头用两行独占的 `+++` 包围 TOML 头部：`tools` 必须是工具名数组，可填 `delegate_subtask`、`set_timer`、`cancel_timer`、`bash`，或填 `[]` 不启用工具；`description` 是角色分工，子角色必填非空描述，主角色可省略。只有主角色也能启动，这时不向模型提供委派工具。
- 结束分隔线后的 Markdown 正文原样作为该角色的系统提示词，包括空行与换行。角色文件限 32 KiB，格式或工具名无效会在启动时报告对应文件。**角色正文和用于选择子角色的描述会发给模型服务，不要放入密钥、凭据或隐私信息，只在可信工作目录启动。**

## 用户工作区与 Bash

- 顶层 `workspace_root = "workspaces"` 设置共同根目录，省略时使用相同默认值。相对路径以配置文件所在目录为准。程序按通道核验的用户键生成 SHA-256 子目录（飞书使用对端 `open_id`），同一用户的主、子 Agent 共用。目录首次使用时创建，不随会话关闭删除；没有通道用户的内置演示不使用工作区。工作区不能位于 `agent_companion` 程序源码或安装包内；配置错误会在首次调用时返回 `workspace_unavailable`。
- 在需要 Bash 的主或子角色文件头部给 `tools` 加上 `"bash"`，例如 `tools = ["delegate_subtask", "bash"]`（主角色）或 `tools = ["bash"]`（子角色）。默认示例不启用。定时器唤醒与子任务回投也可调用，程序不另设联系人白名单。
- `bash` 接收 `command` 和可选整数 `timeout`（秒，1–120，默认 30），时限包含子进程内的工作区准备和切换目录。同一用户的命令串行，不同用户可并行；Runtime 等到工具终态才请求下一轮模型。退出码、标准输出、标准错误和超时、超限标志随工具结果返回，输出两路合计最多 32 KiB 原始字节；到达超时或超过输出上限会终止执行，不自动重试。结束或取消时清理并确认同一进程组已停止；如果无法有界确认，则返回 `bash_cleanup_unconfirmed`，此进程内不再为该工作区启动 Bash（即使会话重新绑定）。请先在宿主机确认旧进程已退出，再重启服务。主动脱离原进程组的进程不在检查范围内。
- **工作区只是每次命令的起点，不是沙箱。** Bash 不加载登录配置或继承服务环境，`HOME` 指向工作区，`PATH` 固定为 `/usr/bin:/bin:/usr/sbin:/sbin`。但命令仍以服务账号的权限执行，可能访问其他目录、凭据和网络。只有明确接受这一风险的部署才应启用，并自行管理 IM 联系人。命令和输出不写入应用日志，但工具调用及输出会保存在会话历史中并可回传给模型服务，不应输出密钥或隐私数据。

## 运行时边界

每条回复首次交接时单独选路，工具续轮的回复也一样：语音按回执结算，飞书文字落库后后台发送。按 `ReplyInfo` 区分回复、运行和会话；其中时间戳是模型请求开始前的事件循环单调时间。纯工具响应不投递。SQLite 原子提交助手记录和对应工具结果，不自动重放已中断的模型调用或外部发送。

允许使用 `delegate_subtask` 的 Agent 可以用 `agent` 选角色创建子 Agent，或用 `agent_id` 复用已有的直属子 Agent，两种方式都须传 `prompt`。受理立即返回 `agent_id` 和 `delegation_id`，不等待结果；`run_id` 在实际运行时生成。每个 Agent 串行处理输入，不同 Agent 可并行。新委派和下级回复进入同一队列，运行中在工具结算后有续轮的安全边界纳入，空闲时开启新运行。子 Agent 的每轮最终回复或错误发至直属父级；角色允许时，可信的下级回投可触发下一次委派。

用 `History.delegation(delegation_id)` 和 `History.agent_run(run_id)` 核对受理、运行与回投。`reply_enqueued_at` 表示回投已入队，不代表已消费。终态先写入 SQLite 再回投；持续写入失败只记录诊断，不重复执行模型、工具或回投。关闭时停止受理和回投，未结算工作标记中断，重启不补跑或补投；本版持久化的 Agent 及其历史可继续复用。已绑定角色缺失时不能复用该子 Agent，恢复同名文件并重启后可继续；如果没有任何子角色，则委派工具不提供给模型。

主角色白名单包含 `set_timer` 时，主 Agent 可登记定时器。默认单次触发，`interval_seconds` 必须是有限正数，可以是小数；循环时传 `mode: "repeat"`，间隔至少 1 秒，并指定 `max_fires`（1–100 的整数，含两端）。单次和循环合计每个会话最多 8 个活跃定时器，取消或完成后释放名额。`message` 可选，登记立即返回 `timer_id`。

到期只向调度器投递 `timer_fired`，最后一次带 `completed` 状态和说明。消息可唤醒空闲 Runtime，也可能在当前工具续轮被处理；语音输入期间可暂存，模型处理时间不作保证。只有含真实用户输入的运行能登记，`cancel_timer` 可用 `timer_id` 停止本会话的后续触发，不撤回已投递消息。会话解绑即撤销回调，进程重启不会恢复定时器；事件循环延误时，循环定时器从实际交接起计算下一次，不集中补发。

历史查找可叠加时间范围和 FTS5 关键词筛选，默认使用 SQLite 的分词规则，不承诺中文短词的子串查找。模型请求不检查本机 HTTP 正文字节上限，也不按本地总 token 估算裁剪图片或历史。飞书入口的媒体限制仍然生效；过大的模型请求仍可能被服务端拒绝。

压缩请求独立组装，沿用正常请求的系统提示词、已有摘要格式、工具定义顺序和推理设置。只发送待压缩的旧历史，在末尾追加内部压缩指令；不带保留尾部和当前轮输入。兼容旧历史按原协议投影；不兼容的 DeepSeek 旧块只以可见内容作为归档材料，不伪造私有推理字段。压缩不执行工具；生成、落库失败时不推进摘要覆盖点，普通请求保留已有摘要和未压缩历史。

压缩指令要求模型不归纳私有协议字段。客户端会拒绝明显原样回显（摘要全文与字段相同，或原样包含较长字段），不保存该摘要、不推进覆盖点；对模型改写、截取或自行生成的文字，不能保证识别。

`[runtime].context_budget` 是软阈值：同一会话上次成功普通请求的实际输入 token 数达到阈值后，下一次普通请求前才尝试压缩。这个数字随普通回复结果保存到 SQLite，摘要请求的用量不参与判断；上次没返回用量时不使用本地估算兜底。`tail_budget` 仍按 UTF-8 字节数除以 3 加固定开销，从近到远保留完整消息块；当前轮不会因超过尾部预算被截断。会话摘要完整保存和发送，不按本地估算截断或分批。配置阈值时给下一轮输入和输出留出余量。升级时请从本机配置的 `[runtime]` 移除旧的 `summary_budget`。
